

**1. PART의 목적**

관리자 업무의 요청·승인·실행·복구 과정에서 다음 사항을 통제하는 것이 목적임

- 업무별 수행 주체와 권한 범위 명확화
- 사용자 역할과 센터 범위에 따른 접근 제한
- 요청자와 승인자 분리를 통한 자기승인 방지
- 임시·긴급 권한의 유효기간 관리
- 중복 요청과 동시 변경에 따른 데이터 불일치 방지
- 변경 전후 데이터와 처리 과정의 감사 이력 보존
- 장애 발생 시 외부 상태 확인에 근거한 재처리

| 세부 구분 | 주제 | 설계 대상 |
|---|---|---|
| 1-1 | 관리자 권한·승인·감사 이력 | 변경 요청부터 승인·적용·이력 확인까지의 업무 흐름 |
| 1-2 | 사용자·역할·센터·승인·이력 연결 | 업무 주체와 데이터의 연결 관계 |
| 1-3 | 자기승인 방지·권한 만료 검증 | 부적절한 요청 차단과 중복 처리 방지 |
| 1-4 | 권한·감사·장애 조치 관리자 화면 | 권한 관리, 감사 조회, 장애 재처리 기능 |
| 1-5 | 권한 범위·승인 분리·긴급 접근 | 접근 범위, 승인 방식, 대체 승인, 긴급 권한 정책 |

| 업무 권한 | 특정 동작을 수행할 수 있는 권한 | 조회·작업·변경·승인·강제 처리 등을 구분 |

| 승인 분리 | 요청과 승인을 서로 다른 주체가 수행하는 구조 | 동일 요청의 자기승인 차단 |
| 권한 유효기간 | 부여된 권한이 효력을 가지는 기간 | 실제 처리 시점의 서버 시각으로 검증 |

| 버전 | 데이터 변경 차수를 식별하는 값 | 요청 당시 정보와 현재 정보의 차이 확인 |
| 감사 이력 | 업무 행위와 결과를 추적하기 위한 기록 | 행위자·대상·사유·변경 전후 값·처리 결과 저장 |
| 긴급 접근 | 예외 상황에서 제한적으로 부여하는 임시 권한 | 최소 범위·최단 기간·사용 기록·사후 검토 적용 |
| 재처리 | 실패하거나 미완료된 작업을 다시 수행하는 행위 | 현재 상태와 기존 처리 결과 확인 후 실행 |

**3. 세부 주제별 설명**

**1-1. 관리자 권한·승인·감사 이력**

상품 가격 변경을 기준으로 요청·승인·적용·감사 조회의 기본 흐름을 정의함

| 단계 | 처리 주체 | 업무 내용 | 생성·변경 정보 |
|---|---|---|---|
| 변경 요청 | U01 상품 담당자 | G01 상품 가격을 10,000원에서 9,000원으로 변경 요청 | 변경 전후 가격, 사유, 요청자, 센터 |
| 승인 검토 | U02 승인 권한자 | 요청 내용과 사유를 검토하여 승인 또는 반려 | 승인자, 처리 시각, 결과 |
| 가격 적용 | 시스템 | 승인된 가격을 반영하고 버전을 V2로 갱신 | 현재 가격, 적용 버전 |
| 감사 조회 | 감사 이력 조회 권한자 | 요청·승인·적용 과정과 이전 값 확인 | 조회 기록은 별도 정책에 따라 저장 |
| 현장 확인 | 매장 담당자 | 매장 화면과 가격 표시의 반영 여부 확인 | 반영 상태와 불일치 여부 |

변경 요청 권한과 승인 권한은 별도로 관리 상품 담당자의 변경 요청 권한은 해당 요청의 승인 권한을 미포함

변경 요청  
→ 요청자 권한·센터 범위 검증  
→ 승인 대기  
→ 별도 승인자의 검토  
→ 승인 또는 반려  
→ 승인된 가격 적용  
→ 버전 갱신·감사 이력 저장  
→ 현장 반영 확인

| 통제 기능 | 권한 주체·대상 | 처리 규칙 |
|---|---|---|
| 자기승인 차단 | 요청자 U01 | 본인이 등록한 요청의 승인 금지 |
| 타센터 접근 차단 | G01만 허용된 사용자 | 권한이 없는 G02의 조회·변경 차단 |
| 긴급 권한 부여 | 권한 부여 권한자 → 대상 사용자 U03 | 대상 센터, 허용 업무, 사유, 시작·만료 시각, 승인자 지정 |
| 긴급 권한 사후 검토 | 지정 검토 담당자 | 사용 내역, 부여 사유, 범위 적정성, 재발 방지 사항 확인 |
| 개인정보 마스킹 | 감사 조회 화면 이용자 | 개인정보 포함 항목에 마스킹 적용 |
| 이력 내보내기 | 별도 내보내기 권한자 | 조회 권한과 다운로드 권한 분리 |

**구현 보완 제안**

- 승인 대기 정보와 현재 적용 가격을 분리
- 승인 실행 시 승인자의 현재 권한과 대상 센터 범위를 재검증
- 승인 완료와 가격 적용 완료를 별도 상태로 관리
- 매장·앱·PDA의 적용 버전과 반영 지연 여부를 확인할 수 있도록 구성
- 긴급 권한 사용 중에도 동일 요청의 자기승인 금지 규칙을 유지

**1-2. 사용자·역할·센터·승인·이력 연결**

사용자, 역할, 센터, 상품, 변경 요청, 승인, 버전, 감사 이력의 관계를 정의함

| 데이터 | 자료의 예시 | 의미 |
|---|---|---|
| 사용자 | U01, U02 | 요청과 승인을 수행하는 사용자 |
| 역할 | MD, 승인자 | 사용자의 업무 유형 |
| 센터 범위 | G01 허용, G02 거절 | 업무 권한을 행사할 수 있는 범위 |
| 상품 | P1001 | 가격 변경 대상 |
| 변경 요청 | CH01 | 변경 전후 가격과 사유를 포함한 요청 |
| 승인 | U02의 승인 | 변경 요청에 대한 검토 결과 |
| 버전 | V1 → V2 | 상품 정보의 변경 차수 |
| 감사 이력 | AUD01 | 변경 과정과 이전 값의 기록 |
| 계정 상태 | 활성·비활성 | 현재 계정의 접근 가능 여부 |

권한은 역할과 접근 범위를 함께 적용하여 판단 MD 역할을 보유하더라도 허용 센터가 G01로 제한된 경우 G02의 상품 정보에는 접근불가

U01의 MD 역할·G01 권한 확인  
→ P1001 가격 변경 요청 CH01 등록  
→ 대상 센터 검증  
→ U02 승인  
→ 상품 정보 V2 적용  
→ 매장 PDA·가격 표시 반영  
→ AUD01에서 변경 과정 확인

퇴사 등으로 계정이 비활성화된 경우에는 세션 종료와 역할·권한 회수를 수행하고 이후 업무 요청을 차단

| 이력 관리 항목 | 자료의 내용 | 설계 기준 |
|---|---|---|
| 원본 보존 | 보존정책에 따른 기존 이력 유지 | 현재 값 변경 후에도 과거 기록 보존 |
| 정정 기록 | CH02 등 새로운 기록으로 정정 | 기존 기록을 덮어쓰지 않고 정정 관계 연결 |
| 전후 비교 | V1·V2 가격 비교 | 변경 항목과 변경 내용을 식별할 수 있도록 표시 |
| 퇴사 후 접근 차단 | 세션 종료·역할 및 권한 회수 | 기존 로그인 상태의 후속 요청도 차단 |

**구현 보완 제안**

- 요청자 비활성화 시 미처리 요청의 취소·인계 정책을 정의함
- 승인자의 센터 이동이나 권한 회수 여부를 승인 실행 시 재검증
- 사용자 이름과 역할이 변경되어도 당시 행위자와 권한 맥락을 확인할 수 있도록 기록
- 동일 상품에 복수 요청이 존재하면 기준 버전을 비교하여 오래된 요청을 재검토 대상으로 처리

**1-3. 자기승인 방지·권한 만료 검증**

권한 범위 위반, 자기승인, 만료된 권한 사용, 동일 요청 반복을 차단

| 검증 시나리오 | 행위 주체 | 판단 조건 | 기대 결과 |
|---|---|---|---|
| 다른 센터 가격 변경 | G01 담당자 | G02 접근 권한 없음 | 요청 거절, 기존 가격 10,000원 유지 |
| 자기승인 | 요청자 U01 | 요청자와 승인자가 동일 | 승인 시도 차단, 요청은 승인 대기 유지 |
| 별도 승인 | 승인 권한자 U02 | 권한·센터 범위 등 검증 통과 | 변경 가격 9,000원 적용 |
| 임시 권한 만료 | 임시 권한 사용자 | 17:00 만료 후 17:01 요청 | 요청 거절 |
| 동일 요청 반복 | 승인 요청자 | 동일 요청의 기존 처리 결과 존재 | 가격 적용 1회, 유효 승인 결과 1건 유지 |

자기승인 시도의 차단과 요청 자체의 반려는 구분 자기승인 시도만 차단된 요청은 승인 대기 상태를 유지하며, 다른 적격 승인자가 검토가능

권한 검증은 화면 진입 시점뿐 아니라 서버의 실제 처리 시점에도 수행

| 검증 항목 | 확인 내용 |
|---|---|
| 계정 상태 | 활성 계정 여부 |
| 업무 권한 | 요청한 동작의 수행 권한 보유 여부 |
| 센터 범위 | 실제 대상 데이터의 센터가 허용 범위에 포함되는지 여부 |
| 권한 유효기간 | 서버 시각 기준 권한 유효 여부 |
| 승인 분리 | 요청자와 승인자의 동일 여부 |
| 요청 상태 | 현재 승인 가능한 상태인지 여부 |
| 중복 처리 | 동일 요청의 완료 여부 |
| 기준 버전 | 요청 당시 버전과 현재 버전의 일치 여부 — 구현 보완 제안 |

| 기록 구분 | 중복 요청 처리 기준 |
|---|---|
| 실제 가격 변경 | 동일 요청으로 한 번만 실행 |
| 유효 승인 결과 | 중복 생성 금지 |
| 반복 호출·차단 기록 | 필요 시 별도 감사·접근 기록으로 저장 |

**구현 보완 제안**

- 버튼 비활성화와 별개로 서버에서 요청 ID와 상태를 확인
- 동시 승인 시 하나의 승인만 유효하게 처리되도록 상태 전환을 통제함
- 가격 적용과 관련 기록 저장의 일부만 성공하지 않도록 정합성을 보장함
- 완료 응답 유실 후 재요청된 경우 기존 처리 결과를 반환
- 권한 유효 구간은 `시작 시각 이상, 만료 시각 미만` 등으로 명확히 정의함
- 검증 결과는 응답 메시지뿐 아니라 가격·버전·요청 상태·승인 건수·감사 이력으로 확인

**1-4. 권한·감사·장애 조치 관리자 화면**

관리자 화면은 권한 관리, 감사 로그 검색, 장애 조치 재처리 기능으로 구분

**① 권한 관리**

| 기능 | 처리 주체 | 입력·표시 정보 |
|---|---|---|
| 권한 변경 요청 | 권한 변경 요청 권한자 | 대상 사용자, 센터, 요청 권한, 사유 |
| 유효기간 지정 | 요청자·승인자 | 시작·만료 시각 또는 일반 권한의 만료 미정 여부 |
| 승인·거절 | 권한 부여 승인자 | 요청 범위, 필요성, 사유, 기간 |
| 권한 적용 | 시스템 | 승인된 업무 범위와 유효기간 |
| 변경 전후 비교 | 요청자·관리자 | 기존 권한과 추가·회수 권한 |
| 처리 상태 확인 | 요청자·승인자 | 승인 대기·승인 완료·권한 거절 |

상품 가격 변경 권한과 고객 연락처 조회 권한은 독립적으로 관리 가격 입력란의 활성화는 승인 없는 즉시 적용 권한을 의미하지 않으며, 실제 반영 방식은 운영 정책에 준수

**구현 보완 제안**

- 자신의 권한을 직접 확대할 수 없도록 요청과 승인을 분리
- 승인자는 자신에게 부여된 권한 위임 범위를 초과하여 승인할 수 없도록 제한
- 고객 연락처 원문 열람에는 별도 권한과 사용 기록을 적용
- 긴급 권한의 만료 시각은 필수로 지정함
- 일반 권한의 만료 미정 허용 여부는 별도 정책으로 결정함

**② 감사 로그 검색**

| 기능 | 표시·처리 내용 |
|---|---|
| 조건 검색 | 기간, 작업 유형, 검색어 |
| 목록 조회 | 일시, 작업 유형, 대상, 변경 전후 값, 요청자, 승인자, 결과 |
| 상세 조회 | 작업 일시, 상품 식별자·바코드, 상품명, 가격, 처리 주체, 결과, 비고 |
| 읽기 전용 | 감사 기록의 직접 수정 제한 |
| 검색 결과 없음 | 조건에 부합하는 기록 없음 표시 |
| 조회 오류 | 조회 실패 원인 또는 재시도 안내 |
| 페이지 이동 | 다수 기록의 분할 조회 |

**구현 보완 제안**

- 검색 결과와 상세 조회에 동일한 센터 범위 통제를 적용
- 검색 결과 없음과 조회 실패를 구분
- 정정이 필요한 경우 원본 수정 대신 신규 정정 기록을 연결
- 내보내기 권한과 개인정보 마스킹 정책을 별도로 적용

**③ 장애 조치 재처리**

외부 결제사에서는 승인이 완료되었으나 내부 주문 확정 처리가 타임아웃으로 실패한 상황을 대상으로 함

| 단계 | 처리 주체 | 처리 내용 |
|---|---|---|
| 실패 작업 확인 | 운영 관리자·장애 조치 담당자 | 작업 ID, 영향 주문, 실패 처리 유형 확인 |
| 외부 결제 조회 | 시스템·외부 PG | 거래번호, 금액, 결제 상태, 조회 시각 확인 |
| 재처리 요청 | 재처리 요청 권한자 | 외부 확인 결과와 재처리 사유 등록 |
| 재처리 실행 | 실행 권한자·시스템 | 확인된 상태에 따라 실패한 내부 작업 수행 |
| 전후 비교 | 운영 관리자 | 결제 상태, 내부 처리 상태, 복구 결과 확인 |

해당 재처리의 대상은 이미 승인된 결제에 대응하는 내부 주문 처리임 외부 결제 승인을 다시 요청하는 동작과 구분

외부 결제 상태가 미확인인 경우 환불 재실행을 차단 필요한 조치 권한이 없는 경우 긴급 권한 요청·승인 절차와 연결

**1-5. 권한 범위·승인 분리·긴급 접근**

접근 범위, 자동 적용, 별도 승인, 대체 승인, 긴급 접근에 관한 운영 정책을 정의함

| 운영안 | 자료의 제안 | 장점 | 검토 사항 |
|---|---|---|---|
| A안 | 역할 기반 권한과 센터 범위 적용, 본사 예외 접근 | 센터별 업무 수행과 접근 통제 병행 | 본사의 예외 접근 범위 명확화 |
| B안 | 허용 기준 내 가격 변경 자동 적용 | 가격 변경의 신속한 반영 | 입력 오류의 즉시 반영 가능성 |
| C안 | 고위험 변경의 별도 승인 | 중요 변경에 대한 통제 강화 | 승인자 부재에 따른 지연 |

A안은 접근 주체와 범위를 정의하며, B·C안은 변경 적용 방식을 정의함 따라서 역할·센터 범위를 기본으로 적용하고 변경 위험도에 따라 자동 적용 또는 별도 승인을 선택하는 구성이 가능 이는 자료 간 내용을 연결한 설계 제안임

| 항목 | 자동 적용 | 별도 승인 |
|---|---|---|
| 처리 주체 | 변경 담당자·시스템 | 요청자·별도 승인자·시스템 |
| 적용 시점 | 허용 조건 충족 시 적용 | 승인 후 적용 |
| 필요 정책 | 허용 금액·비율·업무 범위 | 승인 대상·승인자·대체 승인자 |
| 주요 위험 | 잘못된 변경의 즉시 반영 | 승인 지연 |
| 공통 통제 | 권한·센터 검증, 사유, 감사 이력, 중복 방지 | 권한·센터 검증, 사유, 감사 이력, 중복 방지 |

자료의 `±10% 이내`는 설명용 예시임 자동 적용 금액과 비율은 별도 확정이 필요

승인자 부재 시 U02 → U03 → U04 등의 대체 순서를 사전에 정의함

- 대체 승인자도 해당 업무와 센터의 승인 권한을 보유필요
- 대체 승인자가 요청자와 동일한 경우 승인 대상에서 제외함
- 적격 승인자가 없으면 대기 또는 상위 담당자 검토로 전환함
- 대체 승인 경로와 실제 승인자를 기록

| 긴급 접근 단계 | 처리 주체 | 필수 정보·규칙 |
|---|---|---|
| 요청 | 현장 담당자 | 긴급 사유, 대상 센터, 업무 범위, 사용 기간 |
| 승인 | 본사 등 지정 승인자 | 필요성, 범위, 기간 검토 |
| 사용 | 긴급 권한 사용자 | 승인 범위 내 업무 수행, 작업 로그 기록 |
| 자동 회수 | 시스템 | 만료 시 권한 효력 종료 |
| 사후 검토 | 감사·운영 검토 담당자 | 사용 적정성, 변경 내역, 정책 개선 사항 확인 |

긴급 권한은 시간과 범위가 제한된 권한임 권한 검증, 센터 범위 검증, 자기승인 방지 규칙은 유지

로그 보존 기간 1년, 개인정보 다운로드 정책, 외주·협력사 접근 정책은 확정되지 않은 검토 항목으로 관리

**4. 업무 주체와 권한**

다음 표는 자료의 역할을 실제 구현 관점에서 구분한 권한 설계안임 역할명만으로 모든 권한을 자동 부여하지 않으며, 개별 동작과 접근 범위를 함께 설정함

→ 승인

권한 변경 요청

→ 변경 전후 내역 기록

**장애 재처리**

운영 관리자 실패 작업 확인

**7. 시스템 검증 조건**

| 검증 영역 | 필수 조건 |
|---|---|
| 접근 | 활성 계정이며 대상 동작의 권한을 보유할 것 |
| 범위 | 대상 데이터의 실제 센터·조직이 허용 범위에 포함될 것 |
| 기간 | 처리 시점에 권한이 유효할 것 |
| 승인 | 승인자가 요청자와 다르며 해당 업무의 승인 권한을 보유할 것 |
| 요청 상태 | 이미 완료·반려·취소된 요청이 아닐 것 |
| 변경 충돌 | 요청의 기준 버전이 현재 데이터와 일치할 것 |
| 중복 | 동일 요청의 업무 결과를 중복 생성하지 않을 것 |
| 외부 거래 | 외부 결제 상태와 거래 식별 정보가 확인될 것 |
| 권한 부여 | 승인자가 부여 가능한 범위를 초과하지 않을 것 |
| 긴급 접근 | 기간·범위·사유·승인 정보가 존재할 것 |

**추가 보완 제안:** 승인 후 요청 내용이 변경된 경우 기존 승인을 그대로 적용미실시. 승인 대상 내용을 변경 불가능하게 관리하거나, 변경 시 새로운 요청과 승인 절차를 생성

| 외부 결제 조회 실패 | 상태 미확인으로 보류 | 시스템·운영 관리자 |
| 거래번호·금액·주문 불일치 | 재처리 차단, 조사 대상으로 분류 | 시스템·운영 관리자 |
| 다른 담당자의 선행 복구 | 현재 상태 재확인, 기존 결과 안내 | 시스템 |
| 재처리 반복 실패 | 실패 단계·시도 내역 기록, 무제한 재시도 제한 | 시스템·운영 관리자 |
| 긴급 권한의 만료 후 잔존 | 실행 시 만료 검증으로 차단, 회수 상태 점검 | 시스템·권한 관리자 |
| 적격 대체 승인자 부재 | 대기 또는 상위 검토로 전환 | 운영·승인 관리자 |

**9. 실패 시 처리**

실패 처리는 업무 결과가 확정되지 않은 상태와 이미 확정된 상태를 구분

| 실패 유형 | 처리 기준 |
|---|---|
| 검증 실패 | 업무 변경 없이 거절 결과 반환 |
| 승인 실패 | 승인 결과를 생성하지 않고 기존 요청 상태 유지 |
| 승인 완료 후 적용 실패 | 승인 기록 유지, 적용 실패를 별도 표시 |
| 외부 상태 미확인 | 성공·실패를 추정하지 않고 확인 대기 |
| 중복 요청 | 추가 실행 없이 기존 결과 반환 |
| 동시 변경 충돌 | 현재 데이터와 요청 기준의 차이를 표시하고 재검토 |
| 재처리 실패 | 실패 지점과 시도 내역을 보존하고 후속 조치 판단 |

강제 조치는 일반 재처리와 별도로 통제함 적용 대상, 수행 권한, 승인 필요 여부, 복구 가능성, 필수 기록 항목을 사전에 정의함 이는 구현 보완 제안임

**10. 관리자·운영자 화면에서 필요한 기능**

| 화면 | 필수 기능 |
|---|---|
| 가격 변경 요청 | 현재 값·변경 값 비교, 사유 입력, 요청 상태 조회 |
| 승인 관리 | 승인 대기 목록, 대상 범위 확인, 승인·반려, 자기승인 차단 |
| 권한 관리 | 사용자·역할·센터 설정, 기간 지정, 변경 요청·승인·회수 |
| 긴급 권한 관리 | 긴급 사유, 범위·기간 지정, 만료 확인, 사후 검토 |
| 감사 조회 | 조건 검색, 전후 비교, 요청·승인·적용 연결 조회 |
| 감사 내보내기 | 별도 권한 검사, 마스킹, 다운로드 기록 |
| 장애 관리 | 실패 작업·영향 주문·외부 거래 상태 확인 |
| 재처리 관리 | 현재 상태 확인, 재처리 사유, 실행 결과·시도 내역 조회 |
| 반영 상태 확인 | 매장·앱·PDA의 적용 버전과 지연 상태 확인 |

각 화면에는 사용자에게 허용된 센터·조직·업무 범위를 적용 화면 제어와 별개로 서버에서도 동일한 권한 검증을 수행

**11. 감사 이력**

| 기록 항목 | 저장 내용 |
|---|---|
| 행위자 | 사용자 ID, 당시 역할·권한 맥락 |
| 업무 대상 | 센터, 상품, 주문, 사용자 등 대상 식별자 |
| 수행 동작 | 조회, 변경 요청, 승인, 반려, 권한 부여·회수, 재처리 등 |
| 변경 내용 | 변경 전후 값, 기준 버전, 적용 버전 |
| 처리 사유 | 변경 사유, 반려 사유, 긴급 사유, 재처리 사유 |
| 승인 정보 | 요청자, 승인자, 승인 시각, 대체 승인 경로 |
| 처리 결과 | 성공·실패·차단·보류 및 원인 |
| 연계 정보 | 변경 요청 ID, 작업 ID, 외부 거래번호 |
| 긴급 접근 | 부여 범위, 유효기간, 사용 내역, 회수·사후 검토 결과 |
| 내보내기 | 수행자, 시각, 대상 범위 — 구현 보완 제안 |

감사 기록은 원본을 보존하고 정정 기록을 별도로 연결 개인정보가 포함된 경우 조회·원문 열람·내보내기에 각각 필요한 통제를 적용

업무 결과의 중복 생성 방지와 반복 시도 기록은 별도로 관리 동일 승인 결과는 한 건으로 유지하되 반복 호출이나 차단 시도는 별도 기록으로 추적가능

구현은 다음 순서로 진행하는 방안 토의

2. 가격 변경 요청 → 별도 승인 → 적용 → 감사 조회
3. 자기승인·타센터 접근·권한 만료·중복·동시 변경 검증
4. 권한 요청·부여·회수와 감사 검색 화면
5. 긴급 권한·대체 승인·사후 검토
6. 결제·주문과 연계한 장애 조회·재처리
