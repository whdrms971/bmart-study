**3. 이미지별 세부 주제 분석**

**3-1. 38 — 피크 수요와 센터 작업 수용량**

핵심: **주문 접수 능력과 센터 실물 작업 처리 능력의 차이**

**① 이미지에 나타난 업무와 데이터**

| 구분 | 이미지 내용 | 참여 주체 |
|---|---|---|
| 주문 증가 | 10분 동안 신규 주문 30건 접수 | 고객, 주문 시스템 |
| 운영 현황 | 접수 속도 30건, 피킹 대기 15건, 포장 관련 8건, 기사 대기 6건 표시 | 센터 운영 관리자 |
| 작업 배정 | PDA에서 할당된 피킹 작업과 상품 위치·수량 확인 | 피커 |
| 품질 확인 | 피킹 후 냉장·냉동 상품의 보관 상태와 유통기한 확인 | 센터 작업자 |
| 고객 안내 | 주문 상황에 따라 예상 도착 시간 갱신 | 시스템, 고객 |
| 접수 정책 | 피크 시 일시 접수 제한 가능성 제시 | 정책 담당자, 운영 관리자 |
| 운영 목표 | 고객 불안 감소, 센터 과부하 방지, 상품 품질 유지 | 관련 운영 주체 전체 |

이미지의 운영 콘솔에는 **‘포장 대기’와 ‘포장 중’이 함께 표기**. 구현 시 하나의 수치에 두 상태를 혼용하지 않고 분리 필요

**② 수량 예시와 계산 조건**

이미지의 수량 계산

**기존 대기 5건 + 신규 주문 30건 − 피킹 완료 20건 = 종료 시점 15건**

해당 계산을 **‘피킹 시작 전 대기량’** 공식으로 직접 적용할 경우 집계 오류 발생 가능

| 계산 대상 | 계산 방식 | 주의점 |
|---|---|---|
| 피킹 미완료량 | 시작 미완료량 + 유입 − 피킹 완료 | 대기 중과 피킹 중을 함께 포함할 수 있음 |
| 피킹 시작 전 대기량 | 시작 대기량 + 대기열 유입 − 피킹 시작 | 피킹 완료 수로 차감하면 작업 중 주문이 섞일 수 있음 |

**[구현 보완]** 취소·센터 이관·재작업이 있다면 해당 유입·이탈도 반영 필요

이미지의 `15건`을 적용하기 전 **‘대기’에 포함되는 상태 범위 확정 필요**

**③ 권한과 작업 범위**

| 주체 | 허용할 업무 | 접근 범위·제약 |
|---|---|---|
| 고객 | 주문 생성, 진행 상태·예상 도착 시간 조회 | 본인 주문 |
| 피커 | 배정 작업 조회, 피킹 시작·완료 기록 | 소속 센터의 배정된 작업 |
| 포장 담당자 | 상품·포장 상태 확인, 포장 완료 기록 | 해당 센터에서 포장 가능한 작업 |
| 센터 운영 관리자 | 단계별 작업량 조회, 인력·배정 조정 | 담당 센터 |
| 운영 정책 담당자 | 접수 제한 기준 검토·설정 | 부여된 센터 또는 조직 범위 |
| 시스템 | 작업량 집계, 예상 시간 갱신, 설정된 정책 실행 | 확정된 상태·정책 기준 |

냉장·냉동 품질을 **피커가 어디까지 확인하고 포장 담당자가 무엇을 재확인할지**는 별도로 결정 필요

**④ 정상 처리 흐름**

고객 주문  
→ 주문 접수 확정  
→ 센터 작업 대기열 반영  
→ 피커 배정 및 PDA 확인  
→ 피킹 수행·완료  
→ 보관 상태·유통기한 확인  
→ 포장 및 출하 준비  
→ 기사 대기·인계  
→ 예상 도착 시간 갱신

운영 관리자는 각 단계의 수량과 대기시간을 확인하면서 작업 배정과 인력 운영을 조정

**⑤ 예외·운영 조건**

| 상황 | 필요한 처리 |
|---|---|
| 서버는 정상인데 피킹 대기만 증가 | 센터 병목으로 분류하고 인력·배정·접수 정책 검토 |
| 피킹은 빠르지만 포장 대기가 증가 | 포장 인력·작업대·자재 상태 확인 |
| 포장은 끝났지만 기사가 부족 | 출하·기사 대기와 보관 품질을 함께 확인 |
| 냉장·냉동 상품의 품질 이상 | 해당 상품을 다음 단계로 넘기지 않고 교체·결품 처리 경로로 연결 |
| 집계가 오래되어 실제 대기량과 다름 | 마지막 갱신 시각과 데이터 지연 표시 |
| 임시 인력 증가로 처리 능력이 달라짐 | 변경된 가용 인력과 적용 시간을 반영 |
| 과부하 때문에 품질 확인을 생략하려는 경우 | 품질·안전 절차를 처리량 확보 수단으로 생략하지 않도록 통제 |

**[결정 필요]** 접수 제한 임계값·제한 단위·자동 적용 여부·해제 조건 미확정

**3-2. 39 — 지연 원인과 작업량 데이터 연결**

핵심: **주문 단위 전체 이력 연결과 서버·현장 지연 분리**

**① 주문 9001의 시간 흐름**

| 시점 | 이미지의 사건 | 연결 데이터 |
|---|---|---|
| 14:00 | 주문 접수 | 주문 9001, 접수 이벤트 |
| 14:05 | 피킹 시작 | TASK 01, 작업자 |
| 14:10 | 피킹 완료 | TASK 01의 완료 기록 |
| 14:13 | 포장 완료 | P01 |
| 14:18 | 기사 인계 | H01 |
| 14:30 | 고객 전달 완료 | 주문·배송 완료 기록 |

**주문 9001 → 접수 이벤트 → TASK 01 피킹 → P01 포장 → H01 기사 인계 → 고객 전달 완료**

주문 ID와 작업 ID의 역할 구분 필요. 주문 ID만 저장할 경우 세부 지연 작업 추적에 한계

**② 시간 구간의 올바른 해석**

| 구간 | 경과시간 | 확인 가능한 의미 | 추가로 필요한 기록 |
|---|---:|---|---|
| 접수 → 피킹 시작 | 5분 | 피킹 시작 전 경과시간 | 배정 시각이 있어야 배정 지연과 작업 시작 지연 분리 가능 |
| 피킹 시작 → 완료 | 5분 | 피킹 구간 경과시간 | 중단·재개 기록이 있어야 순수 작업시간 분리 가능 |
| 피킹 완료 → 포장 완료 | 3분 | 포장 대기와 포장 작업을 포함할 수 있음 | 포장 시작 시각 |
| 포장 완료 → 기사 인계 | 5분 | 출하 준비·기사 대기·인계 작업을 포함할 수 있음 | 출하 준비 완료, 기사 도착, 인계 시작 시각 |
| 기사 인계 → 고객 전달 | 12분 | 배송 과정의 경과시간 | 출발·도착·전달 시각 |

전체 경과시간 **30분**

다만 **‘포장에 3분 걸렸다’**, **‘기사 대기만 5분이었다’**고 단정 불가. 현재 자료에는 각 구간 세분화를 위한 시작·종료 기록 부족

**③ 서버 응답시간은 별도로 측정**

이미지의 접수·피킹·포장·인계 서버 응답시간은 모두 **미측정**

| 측정 대상 | 측정 목적 |
|---|---|
| 주문 접수 요청의 응답시간 | 고객이 주문 결과를 받는 데 걸리는 시간 확인 |
| 피킹 시작·완료 요청의 응답시간 | PDA 처리 지연 확인 |
| 포장 완료 요청의 응답시간 | 포장 작업 기록 지연 확인 |
| 기사 인계 요청의 응답시간 | 인계 확정 처리 지연 확인 |
| 이벤트 발생 → 관련 화면 반영시간 | 상태 전파 지연 확인 |

**[구현 보완]** 서버 응답시간이 짧아도 이벤트 처리가 늦으면 운영 콘솔이나 고객 화면의 상태는 오래된 정보일 수 있음 응답시간과 화면 반영 지연을 함께 확인 필요

**④ 작업량 데이터와 연결**

이미지는 10분 구간의 접수 30건·완료 20건·시작 대기 5건·종료 대기 15건을 제시

이 데이터를 주문 이력과 연결할 때는 다음 조건이 필요

- 같은 센터의 데이터인지 확인
- 같은 시간 구간인지 확인
- 주문 건수·작업 건수 혼합 금지
- ‘완료’의 단계별 기준 통일
- 하나의 주문이 여러 작업으로 분할되는 경우 중복 집계 방지
- 취소·이관·재작업을 별도 증감 사유로 관리

**⑤ 예외·권한**

| 상황 | 처리 방법·권한 주체 |
|---|---|
| 동일 완료 이벤트가 반복 수신됨 | 시스템이 이벤트 식별자로 중복 반영 방지 |
| 완료 이벤트가 시작 이벤트보다 먼저 도착함 | 발생·수신 시각과 상태 순서를 확인하고 보정 대상 관리 |
| PDA가 오프라인 상태에서 작업함 | 작업 발생 시각과 서버 수신 시각을 분리 저장 |
| 주문은 존재하지만 연결 작업이 없음 | 운영 관리자가 누락 작업 확인, 권한 있는 담당자가 복구 |
| 다른 센터의 작업 ID를 연결하려 함 | 시스템이 주문·센터·작업 관계를 검증해 거절 |
| 작업 시간을 직접 수정하려 함 | 일반 작업자의 임의 수정 제한, 정정 권한과 사유 기록 |
| 이미 배송 완료된 주문에 피킹 완료가 다시 들어옴 | 정상 상태 전이로 반영하지 않고 중복·지연 이벤트 여부 확인 |

작업 이력 정정은 원본 기록을 덮어쓰기보다 **원본과 정정 기록을 연결하는 방식**을 제안

**3-3. 40 — 성능·과부하·접수 제한 검증**

실제 시험 결과가 아닌 **실행 예정 검증 시나리오 6개**

**① 여섯 가지 검증 항목**

| 번호 | 이미지의 검증 주제 | 검증해야 할 결과 |
|---|---|---|
| 1 | 부하 증가 시 중복·누락 | 결제 중복 0건, 주문 누락 0건인지 확인 |
| 2 | 센터 대기·접수·완료 수량 | 예시의 `5 + 30 − 20 = 15`가 정의된 기준으로 집계되는지 확인 |
