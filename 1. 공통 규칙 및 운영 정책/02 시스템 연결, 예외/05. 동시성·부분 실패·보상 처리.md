

**1. PART의 목적**

**목적: 재고 예약·결제·주문 확정·취소·기사 인계·환불의 부분 실패 및 동시 요청 상황에서 주문·결제금·재고의 일관성 유지.**

**핵심 업무**

- 마지막 재고를 두 고객에 대한 동일 재고 중복 예약 방지
- 결제 성공과 주문 확정 성공을 구분
- 결제만 성공한 경우 주문 복구 또는 환불로 해결
- 취소 확정과 기사 인계 확정이 동시 성공 방지
- 동일 환불·예약 해제 요청이 반복되어도 실제 처리는 한 번만 적용
- 복구 과정과 처리 책임자를 연결해서 추적
- 결과 불명 상태의 임의 실패 확정 금지

**2. 핵심 개념**

| 개념 | 의미 | 구분 필요 사항 |
|---|---|---|
| 현물 재고 `Q` | 센터에 실제로 보유한 상품 수량 | 결제 성공만으로 실물이 줄어들지는 않음 |
| 예약 수량 `R` | 특정 주문을 위해 확보해 둔 수량 | 결제 전 예약과 결제 후 출고 대기 예약을 구분할 필요가 있음 |
| 판매 가능 수량 `A` | 다른 주문에 판매할 수 있는 수량 | 이미지의 단순 모델에서는 `A = Q - R` |
| 재고 예약 | 주문에 필요한 상품을 확보하는 처리 | 예약 성공이 결제 성공이나 주문 확정 성공을 의미하지 않음 |
| 결제 승인 | PG가 결제를 승인한 상태 | 내부 주문 저장에 실패해도 결제는 성공할 수 있음 |
| 주문 확정 | 주문을 정상적으로 이행할 수 있도록 내부 처리를 확정하는 것 | 결제 승인과 별도 상태로 관리 |
| 보상 처리 | 일부 단계가 성공한 뒤 전체 업무가 실패했을 때 수행하는 후속 처리 | 이 이미지에서는 주로 환불과 예약 해제이며, 추가 보상금과는 다름 |
| 멱등성 | 같은 요청을 반복해도 실제 업무 효과가 중복되지 않는 성질 | 재시도로 환불·재고 복원이 추가 발생하면 안 됨 |
| 경합 | 서로 충돌하는 요청이 같은 대상에 동시에 들어오는 상황 | 마지막 재고 경쟁, 취소와 기사 인계 경쟁 |
| 결과 불명 | 응답 유실 등으로 성공 여부를 아직 확인할 수 없는 상태 | 실패 확정과 다름 |

`A = Q - R`: 이미지의 기본 모델. **검수 대기·불량·폐기 대상 재고 관리 시 판매 가능 수량에서 별도 차감 필요.**

**3. 이미지별 세부 분석**

**3-1. 22 — 마지막 재고·부분 실패·보상 순서**

**핵심: 마지막 재고 예약 및 결제 승인 후 주문 확정 실패 시 환불·예약 해제 순서.**

**원본의 정상·실패 흐름**

현물 우유 1개 확인  
→ 고객 A·B 동시 주문  
→ A 예약 성공, B 품절 처리  
→ A 결제 1,950원 성공  
→ 주문 확정 실패  
→ 고객센터에서 PG 거래 조회  
→ 결제 성공 확인 후 환불 요청  
→ 환불 완료 확인  
→ 실물이 남아 있는지 확인  
→ A의 예약 해제  
→ 판매 가능 수량 1개 복원

| 시점 | 현물 `Q` | 예약 `R` | 판매 가능 `A` | 의미 |
|---|---:|---:|---:|---|
| 주문 전 | 1 | 0 | 1 | 판매 가능 |
| A 예약 성공 | 1 | 1 | 0 | B에게 추가 판매 불가 |
| A 결제 성공 | 1 | 1 | 0 | 출고 전이므로 현물 유지 |
| 주문 확정 실패 | 1 | 1 | 0 | 환불 처리 중 예약 유지 |
| 환불 완료·예약 해제 | 1 | 0 | 1 | 실물 확인을 전제로 판매 가능 복원 |

**주체와 권한**

| 주체 | 업무·권한 | 접근 범위 |
|---|---|---|
| 고객 A | 자신의 주문·결제·환불 상태 조회 | 본인 거래 |
| 고객 B | 주문 시도, 품절 결과 확인 | 본인 요청 |
| CS 담당자 | 주문·PG 결과 조회, 정책에 따른 환불 요청 | 담당 고객지원 범위 |
| 재고 담당자 | 실물 재고 확인, 예약 상태 확인 | 담당 센터·상품 |
| 시스템 | 예약 경쟁 제어, 상태 검증, 환불 결과 반영, 예약 해제 | 해당 주문·예약·거래 |
| 외부 PG | 원거래 조회 결과 제공, 환불 처리 | 해당 가맹점 거래 |
| 운영 관리자 | 미완료 환불·예약 해제 실패 확인 | 부여된 운영 범위 |

**원본 미명시: 환불 별도 승인자 필요 여부, 자기승인 허용 여부, 임시 권한 사용 여부.**

**구현 보완**

- 환불 요청 전송만을 근거로 한 환불 완료 처리 금지
- 환불 결과가 불명확하면 조회를 통해 확인하고 예약을 유지
- 환불은 완료됐지만 예약 해제가 실패했다면 **예약 해제만 재처리**수행
- 실물 분실·파손 시 예약 해제 여부와 무관하게 즉시 판매 가능 재고 전환 금지
- 처리 중 추가 입고 발생 시에도 해당 주문의 예약 1개만 해제. 총재고의 과거 값 덮어쓰기 금지

**운영 화면·감사 이력**

주문번호·결제 상태·주문 확정 실패 사유·PG 승인번호·환불 상태·예약 상태·실물 확인자·처리 담당자·단계별 처리 시각의 통합 조회 필요

**3-2. 23 — 마지막 한 개 동시 주문 경쟁**

**핵심: 마지막 재고 1개에 대한 동시 주문 시 단일 고객 예약 허용.**

**원본 흐름**

`Q=1, R=0, A=1`  
→ A·B 동시 구매 요청  
→ 한 요청만 예약 성공  
→ `Q=1, R=1, A=0`  
→ 예약 성공 고객만 결제 진행  
→ 결제 성공 시 출고 대기  
→ 정상 출고 완료 시 `Q=0, R=0, A=0`

**별도 실패 흐름**

결제 실패 **확정**  
→ 예약 해제  
→ `Q=1, R=0, A=1`

**주체와 권한**

- **고객:** 주문·결제 요청 가능. 재고 예약 성공 여부의 직접 결정 불가
- **시스템**은 해당 센터·상품의 판매 가능 수량을 검증하고 예약을 확정수행
- **운영 관리자·재고 담당자**는 권한 범위 내에서 현물·예약·판매 가능 수량과 예약 이력을 조회
- **외부 PG**는 예약 성공 고객의 결제 요청을 처리

**시스템 검증 조건**

| 조건 | 필요한 처리 |
|---|---|
| 동일 재고에 동시 예약 요청 | 수량 확인과 예약 반영을 하나의 원자적 처리로 수행 |
| 예약 실패 고객의 결제 요청 | 결제 진행 차단 |
| 동일 고객이 구매 버튼 반복 클릭 | 같은 요청의 예약이 중복 생성되지 않도록 처리 |
| PG 응답 없음 | 실패로 단정하지 않고 거래 조회 |
| 결제 승인 후 출고 전 | 예약 유지 |
| 결제 실패 확정 | 해당 예약만 해제 |
| 정상 출고 완료 | 현물과 예약 수량을 함께 차감 |

**구현 보완**

두 요청이 각각 `A=1`을 조회한 뒤 예약 수량을 증가시키는 방식은 중복 예약 위험 존재. **조건부 갱신 또는 적절한 잠금을 통한 예약 반영 시점의 동시성 제어 필요.**

일반 예약: 시스템 자동 판단 대상, 별도 인적 승인 대상과 구분. 관리자 수동 재고·예약 보정 권한: 별도 설계 필요

**운영 화면·감사 이력**

센터·상품별 `Q/R/A`, 예약 주문, 예약 생성·만료 시각, 결제 상태, 예약 성공·실패 사유 표시. 예약 실패 요청 추적 기능 필요

**3-3. 24 — 취소와 기사 인계의 동시 요청**

**핵심: 동일 주문의 취소 확정과 기사 인계 확정에 대한 상호 배제.**

**참여 주체**

| 주체 | 역할·권한 |
|---|---|
| 고객 | 본인 주문의 취소 요청 |
| CS 담당자 | 취소 접수, 현재 처리 상태 조회, 회수·반품 안내 |
| 피커 | 담당 주문의 피킹 완료 기록, 취소 시 상품 반납 |
| 품질 확인 담당자 | 반납 상품의 상태 확인 |
| 인계 담당자 | 담당 센터의 출하 상품과 기사 인계 대상 확인 |
| 배송기사 | 배정받은 주문의 인계 확인 요청 |
| 관제·운영 관리자 | 충돌 현황과 최종 결과 조회, 예외 업무 조정 |
| 시스템 | 현재 상태와 정책에 따라 상충하는 상태 전이 제어 |

**A. 취소 확정이 먼저 처리된 경우**

취소 확정  
→ 기사 인계 요청 거절  
→ 피킹 상품 반납  
→ 상품 품질 확인  
→ 환불 별도 요청

**취소 확정과 환불 완료의 구분 필수.** 상품 반납·품질 확인·환불 요청의 개별 추적 필요

**B. 기사 인계 확정이 먼저 처리된 경우**

기사 인계 확정  
→ 즉시 취소 거절  
→ 배송 중 고객지원  
→ 정책에 따라 회수·반품 접수

**거절 대상: 해당 시점의 즉시 취소.** 이후 회수·반품 가능성은 별도 정책에 따라 판단

**시스템 검증 조건**

- 고객 휴대폰·기사 PDA 표시 시각만을 근거로 한 최종 승자 결정 금지
- 서버에서 동일 주문에 적용하는 상태 전이 규칙과 동시성 제어가 필요
- 취소 확정 이후 인계 확정으로 바뀌면 안 됨
- 인계 확정 이후 같은 즉시 취소 요청이 성공금지
- 피킹 완료와 기사 인계 완료는 다른 상태
- 일반적인 기사 배정과 실제 상품 인계도 구분필요

**구현 보완**

| 예외 | 처리 |
|---|---|
| 기사 인계는 실제로 끝났는데 PDA 응답이 유실됨 | 인계 기록과 실물 이동을 조회·확인하고 자동 취소를 보류 |
| 취소 후 피킹 상품이 반납되지 않음 | 반납 대기 유지, 판매 가능 복원 보류 |
| 반납 상품이 파손·변질됨 | 정상 판매 재고로 복원하지 않고 품질 판정 결과 반영 |
| 취소·인계 요청이 반복 전송됨 | 기존 처리 결과 반환 |
| 다른 센터 직원 또는 미배정 기사가 요청 | 범위 검증 후 거절 |
| 운영자가 최종 상태 변경을 시도 | 일반 수정과 분리된 예외 처리 절차 적용 |

**원본 미명시: 별도 승인·자기승인·임시 권한 정책.** 강제 상태 변경 기능 도입 시 요청자·승인자 분리 및 사유 기록 권장

**감사 이력**

취소 요청 ID·인계 요청 ID·주문번호·요청자·기사·인계 담당자·서버 접수·확정 시각·변경 전후 상태·거절 사유·반납·품질 확인·환불 연결 정보 기록

**3-4. 25 — 결제 성공 후 주문 확정 실패 복구**

**핵심: 결제 승인 후 주문 확정 실패 거래의 복구 경로(동일 주문 재확정 또는 환불) 선택.**

**공통 확인 흐름**

결제 11,000원 성공  
→ 주문 확정 실패  
→ 운영자가 PG 원거래 조회  
→ 승인 성공 확인  
→ 주문 존재 여부·중복 위험·재고 상태 확인  
→ 복구 경로 선택

| 경로 | 수행 내용 | 최종 결과 |
|---|---|---|
| A. 동일 주문 재확정 | 기존 거래와 연결된 동일 주문을 복구 | 주문 1건 확정, 추가 결제 없음, 환불 없음 |
| B. 환불 | 원거래 환불 요청, 완료 확인 후 예약 2개 해제 | 환불 완료, 현물 보존, 예약 해제 |

**A. 재확정 경로**

- 동일 주문 식별자로 재시도수행
- 이미 주문이 생성되었는지 먼저 확인
- 중복 주문 생성 금지
- 고객 결제금액은 11,000원 그대로 유지
- 예약 재고를 유지
- 재확정 성공 거래의 보상 환불 동시 실행 금지

**B. 환불 경로**

- 원결제에 연결된 환불을 요청수행
- 환불 진행 중에는 완료 누적액을 0원으로 표시
- 완료 확인 후 누적 환불액을 11,000원으로 반영
- 원본 예시에서는 환불 완료 후 예약 2개를 해제수행

**주체·권한**

- **운영 담당자**: PG 조회, 복구 가능 여부 확인, 허용된 재확정·환불 요청
- **시스템**: 중복 주문 방지, 복구 경로 충돌 방지, 금액·예약 검증
- **외부 PG**: 결제·환불 결과 제공
- **재고 담당자**: 필요 시 실물과 예약 불일치 확인
- **고객**: 처리 중 상태와 최종 결과 확인

**구현 보완**

| 반납·품질 확인 | 대상 상품, 수량, 담당자, 판정 | 반납 확인, 재판매 가능 여부 |
| 권한·승인 | 사용자, 역할, 센터 범위, 유효기간, 승인 대상 | 승인·반려·만료·회수 |
| 고객 안내 | 대상, 안내 유형, 채널, 발송 결과 | 진행·완료 안내 기록 |
| 감사 이력 | 행위자, 대상, 전후 상태, 사유, 시각 | 업무 변경 이력 추가 |

**주문·결제·예약·환불·복구 상태의 분리 관리 필요.**

**동일 거래의 병존 상태 예시**

| 구분 | 상태 예시 |
|---|---|
| 결제 | 승인 완료 |
| 주문 | 확정 실패 |
| 복구 | 환불 경로 진행 중 |
| 환불 | 요청됨 |
| 재고 예약 | 유지 중 |

‘주문 실패’ 단일 상태로 관리 시 결제·재고 관련 후속 업무 누락 위험

**6. 정상 업무 흐름과 복구 흐름**

**기본 흐름 예시: 결제 직전 예약 정책 선택 기준.**

고객 주문 요청  
→ 고객·센터·상품·가격 검증  
→ 재고 예약  
→ 결제 승인  
→ 주문 확정  
→ 피킹  
→ 포장·출하 준비  
→ 기사 인계  
→ 배송

현물 차감 기준인 **출고 완료와 기사 인계의 관계 명확화 필요.** 동일 단계·별도 단계 설정에 따른 재고 차감 시점 차이 존재

**실패 유형별 후속 흐름**

| 실패 유형 | 후속 흐름 |
|---|---|
| 예약 실패 | 결제 차단 → 품절 안내 |
| 결제 실패 확정 | 예약 해제 → 재구매 가능 |
| 결제 결과 불명 | PG 조회 → 결과에 맞춰 처리 |
| 결제 성공·주문 확정 실패 | 거래 조회 → 동일 주문 재확정 또는 환불 |
| 취소·인계 경합 | 하나만 확정 → 나머지 거절·후속 경로 안내 |
| 환불 완료·예약 해제 실패 | 예약 해제만 재처리 |

**7. 시스템 검증 조건**

| 검증 영역 | 필수 조건 |
|---|---|
| 재고 | 단순 모델에서 `Q ≥ 0`, `R ≥ 0`, `R ≤ Q` 유지 |
| 예약 | 같은 주문 요청에 예약 효과 중복 적용 금지 |
| 결제 | 예약 실패 주문의 결제 차단, 승인 중복 방지 |
| 주문 | 동일 요청으로 중복 주문 생성 금지 |
| 복구 | 재확정과 실패 보상 환불의 충돌 방지 |
| 환불 | 총환불액이 원결제의 환불 가능 금액을 초과하지 않음 |
| 예약 해제 | 같은 예약의 수량 복원은 한 번만 적용 |
| 상태 전이 | 취소 확정과 인계 확정의 동시 성공 금지 |
| 범위 | 고객 본인 거래, 직원 센터·업무 범위, 기사 배정 검증 |
| 승인 | 승인받은 내용과 실제 실행 내용 일치 |
| 동시 수정 | 처리 중 다른 작업이 변경한 상태를 확인 |
| 권한 | 실행 시점의 만료·회수 여부 확인 |

승인 후 금액·수량·대상 주문 변경 시 기존 승인에 따른 실행 금지 및 재검토 필요

**12. 핵심 정리**

**구현 핵심: 단일 주문·환불 버튼이 아닌 다음 업무 기능의 연계.**

- **재고 예약:** 같은 재고가 중복 판매되지 않도록 처리
- **상태 분리:** 결제·주문·예약·환불 상태를 따로 관리
- **복구 경로 제어:** 동일 주문 재확정과 실패 보상 환불의 충돌 방지
- **멱등 처리:** 반복 요청에도 환불·재고 복원은 한 번만 적용
- **취소·인계 제어:** 상충하는 두 확정 중 하나만 허용
- **운영 복구:** 실패한 단계만 확인하고 재처리
- **권한·감사:** 누가 어떤 범위에서 무엇을 했는지 기록

**구현 전 우선 확정 정책: 예약 시점·예약 만료 조건·출고 차감 시점·재확정 허용 조건·수동 조치 권한·고객 안내 기준.**
