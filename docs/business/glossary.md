# 공통 용어집 (Glossary)

> 문서 간 용어 차이를 정리한 기준표. 괄호 안은 원문서에서 쓰인 다른 표기.
> 코드·API·이벤트 명칭은 이 표의 **표준 표기**를 따른다.

## 1. 조직·시설

| 표준 표기 | 다른 표기 | 정의 |
|---|---|---|
| **PMart** | 바로픽(Commerce·SCM 문서), B마트(Delivery 문서, 외부 참고 브랜드) | 본 프로젝트의 서비스명. Delivery 문서의 B마트·배민커넥트 수치는 외부 참고값이며 확정 정책이 아니다 (BackOffice 0.4). |
| **CDC** | DC, 칠곡 DC, Warehouse | 중앙 물류센터. 초기 1곳(칠곡). 재고 정본은 `cdc-inventory-service`. |
| **MFC** | PPC(Commerce 문서), 점포, 센터, 지정 MFC | 도심 소형 풀필먼트 센터. 초기 부산 5곳, 확장 26곳. 재고 정본은 `mfc-inventory-service`. |
| **MFC Operations** | 현장 시스템, 점원앱/PDA | MFC 현장 작업을 수행하는 시스템 집합(`mfc-*` 서비스). |
| **BackOffice** | 본사, 관제, ICS(통합관제) | 본사 운영자 업무(승인·권한·사건). 정본을 복제하지 않고 연결만 한다. |

## 2. 상품·재고

| 표준 표기 | 정의 |
|---|---|
| **SKU (E-/B-)** | 전역 공통 8자리 일련번호. `E-`=낱개(Each), `B-`=제조사 밀봉 묶음. E/B는 서로 다른 재고이며 전환·합산하지 않는다. 본사 승인 후 발급. |
| **기초상품(baseProduct)** | E/B SKU가 속하는 상위 상품. 구매 상한(구성 낱개 합산 기본 10개)의 판정 단위. |
| **구성 낱개 수** | B- SKU 1개가 포함하는 낱개 수. 구매 상한 계산에 사용. |
| **BOX / PLT / LPN** | 물류 취급 단위(박스·팔레트)와 그 번호. 상품이 아니며 상품 수량과 별도. |
| **LOT** | 제조 로트·소비기한 단위. 식품 필수, 비식품 선택. |
| **LOC** | 센터 내 보관 위치. CDC는 7구간 코드 `센터-온도-구역-랙-베이-단-포지션`. |
| **H / Q / E / R / A** | MFC 재고 기호. H=현물, Q=격리(⊂H), E=판매적합, R=유효 예약, A=E−R(판매 예약 가능량). `0≤R≤E≤H`. |
| **On-hand / Reserved / Held / Available** | CDC 재고 기호. Available=`max(0, E−R−S)`, S=안전량. |
| **Transit (T)** | CDC에서 실제 출발했으나 MFC 수령 대사가 끝나지 않은 수량. `cdc-inventory-service` 소유. |
| **P / Rf** | MFC 예정 입고량과 예정 입고에 대한 약속 배정(1차 미채택). |
| **TOUT** | CDC 실제 출발 전기. `CDC 현물 −q, 예약 −q, Transit +q`를 한 거래로 반영. |
| **TIN** | MFC 실수령 전기. `MFC 현물 +r (정상+격리)`. CDC는 이를 확인한 뒤 `Transit −r`. |
| **TRF** | 승인 이관(Transfer). 1요청·1이관·1출발 원칙. 같은 TRF의 후속 분할 출발 금지. |
| **FEFO** | 소비기한 임박 순 출고. 최소 잔여일수 규칙은 WMS 문서 참조. |
| **MOV** | 센터 내부 이동·선반 보충 작업. 센터 간 공급(TRF)과 구분. |
| **ADJ / CNT** | 승인 재고 조정 / 실사. |

## 3. 주문·결제

| 표준 표기 | 정의 |
|---|---|
| **구매 의도(purchaseIntent)** | 고객의 동일 주문 의도를 식별하는 키. 재전송 시 기존 결과 반환. |
| **주문 초안(draft)** | 결제 진입 전 주문서. 가격·혜택을 생성 시점부터 최대 10분 동결. |
| **재고 예약** | 결제 진입 직전 지정 MFC 전품목 예약. 10분 유효. 가격 동결과 시작 사건이 다르다. |
| **슬롯(arrival window)** | 예약배달 도착 시간대. 정원은 MFC 작업 여력과 라이더 여력 모두를 만족해야 한다. |
| **상품준비 상태** | MFC가 실제 준비 시작을 확정하고 OMS가 반영한 주문 상태. 이후 예약 시간 변경 차단. |
| **인계(handover)** | MFC가 포장을 라이더에게 실제로 넘긴 사실. QR 스캔 전수 확인. 이 시점에 MFC 현물 차감. |
| **출고 전 취소** | 인계 전 중지가 확정된 수량의 취소. 인계된 수량은 회수·반품으로만 처리. |
| **결과 불명(UNKNOWN_RESULT)** | 타임아웃·응답 유실. 실패가 아니며 원요청·원거래 조회로만 해소. |
| **PG** | 결제대행사. 토스페이먼츠만 사용. 승인·취소·환불 사실의 정본. |
| **부분 결제취소** | 부분 품절·반품에 한해 원결제의 해당 품목 안분액을 PG에 부분 취소. 고객 임의 부분 취소는 없음. |
| **첫 구매** | 최종 결제 확인·주문 확정 이력이 없는 계정. 배달팁 무료. 실패·출고 전 전체 취소는 자격 미소진. |

## 4. 배송·운송

| 표준 표기 | 정의 |
|---|---|
| **Delivery (라스트마일)** | MFC→고객 배송. 라이더 배차·수행·회수·ETA. `delivery-*` 서비스. |
| **TMS (미들마일)** | CDC→MFC 간선 운송. 차량·간선기사·운행·정차. `transport-*`, `fleet-service`. 라이더와 자원·ID를 공유하지 않는다. |
| **배송(delivery) / 포장(package)** | 주문 1건은 배송 N건(10kg 초과 분할), 배송 1건은 포장 N개. 포장 수≠배송 수≠결제 수. |
| **배차 시도 / 제안** | 배송 1건에 대한 라이더 탐색 회차와 특정 라이더에게 보낸 제안. 응답 대기 1분. |
| **운행(Trip) / 정차(Stop)** | 간선 실제 실행 단위와 한 장소의 도착·하차·인계·출차. |
| **departureId** | 차량의 실제 출발 사실. 한 차량의 1회 출발에 여러 TRF 출발 구성이 연결될 수 있다. |
| **인계 증빙** | 특정 화물·수량·인계자/인수자·시각·사진. GPS 도착·버튼 클릭과 다르다. |

## 5. 운영·승인

| 표준 표기 | 정의 |
|---|---|
| **승인 단위** | `업무 종류 + 원객체/행 + 대상 범위 + 예상 버전 + 허용 행위 + 수량/금액 + 조건 + 효력/만료`. |
| **승인 정본** | 승인 결과를 소유하는 도메인 서비스(예: 공급 사업승인=`replenishment-service`). BackOffice 승인함은 원승인 ID를 참조만 한다. |
| **사건(Case)** | 여러 도메인에 걸친 운영 이슈의 총괄 단위. 도메인별 사고·클레임은 원시스템에 유지. |
| **의무(Obligation)** | 종결 전 확인해야 할 남은 처리(회수·검수·환불·통지 등). 종류가 다른 수량/금액은 합산하지 않는다. |
| **멱등 키** | `(sourceSystem, requestId)`. 같은 키·같은 본문=기존 결과, 같은 키·다른 본문=충돌 거절. |
| **이벤트 키** | `(sourceSystem, eventId)`. consumer는 inbox 테이블로 1회만 적용. |

## 6. 상태 태그 (문서 공통)

| 태그 | 의미 |
|---|---|
| `[확정 정책]` | 사용자/팀이 확정한 규칙. 설계가 바꾸지 않는다. |
| `[채택 설계]`, `[설계안]`, `[제안]` | 이번 설계에서 채택한 방식. 운영값은 별도 승인. |
| `[가정]` | 설명용 수치. 실제 마스터 값이 아니다. |
| `[팀 확인 필요]`, `확인 필요`, `[결정 필요]` | 근거·승인 부족. 미설정을 0/무제한/정상으로 대체하지 않는다. |
