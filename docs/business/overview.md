# PMart 전체 비즈니스 흐름 (Overview)

> 퀵 커머스(도심 소형 풀필먼트 기반 즉시·예약 배달) 백엔드의 끝에서 끝까지 흐름.
> 상세 규칙은 `docs/business/*-business-logic.md`, 서비스 경계는 `docs/architecture/service-map.md`, 사가는 `docs/business/flows/` 참조.

## 1. 한 줄 요약

본사가 승인한 상품을 **CDC(칠곡)** 에서 **MFC(부산 5곳 → 26곳)** 로 간선 운송(TMS)해 보충하고, 고객은 배송지의 **지정 MFC 현물만** 으로 주문·결제하며, MFC가 피킹·포장해 **라이더(Delivery)** 가 고객에게 전달한다. 취소·반품·환불·공급 승인·사건은 각 도메인 정본이 확정하고 **BackOffice** 는 연결·승인·관제만 한다.

## 2. 두 개의 물류 흐름

```
[공급 흐름 — 미들마일]
  MFC 필요 제시/수동 요청 → SCM 보충 계산·배분·사업승인(TRF)
    → CDC WMS 확보·피킹·검품·상차 → TMS 운행 편성·실제 출발(TOUT)
    → MFC 실수령·검수·적치(TIN) → CDC Transit 대사

[판매 흐름 — 라스트마일]
  고객 탐색·장바구니(Commerce) → 주문 초안·견적(OMS)
    → 재고 예약 + 슬롯/여력 확보 → PG 결제 승인(토스페이먼츠) → 주문 확정
    → MFC 피킹·패킹 → 라이더 배차·QR 인계(MFC 현물 차감) → 전달 완료(사진)
    → 리뷰·알림 / 취소·반품·교환·환불(클레임)
```

두 흐름은 **MFC 재고(H/E/R/A)** 에서 만난다. 공급 흐름은 H를 늘리고(TIN), 판매 흐름은 R을 점유(예약)했다가 인계 시 H와 R을 같은 사건에서 줄인다. 피킹·포장만으로는 H가 줄지 않는다.

## 3. 도메인 책임 한눈에

| 도메인 | 소유하는 정본 | 소유하지 않는 것 |
|---|---|---|
| Commerce | 고객 계정·동의·주소록, 장바구니, 카탈로그/검색/전시, 리뷰, 상품 마스터·가격 버전 | 주문 원장, 재고 예약, 결제 사실 |
| Order & Payment (OMS) | 주문·주문행·금액 스냅샷·고객 약속, 주문 사가 진행 상태, 클레임·환불 의도, PG 거래 원장 | 재고 수량, 현장 작업 사실, 배송 수행 사실 |
| SCM | 수요 예측, 보충 필요량, 센터별 배분, 공급 **사업승인(TRF)**, 공급 이행 판단 | CDC/MFC 재고 수량, 운송 편성, 현장 수령 |
| CDC WMS | CDC 현물·예약·LOT/LOC/LPN, Wave/피킹/검품/상차, **TOUT·Transit 대사**, 품질 격리 | MFC 재고, 공급 승인, 차량 배정 |
| MFC | MFC 현물·예약·품질별 수량, 피킹/패킹/**인계**, 수령·적치(TIN), 작업 여력, 반품 검수 | 주문 취소 판단, 금액, 라이더 배정 |
| TMS | 간선 운송 요청·운행·정차·차량·기사·실제 출발/인계 증빙·온도 | 보충량, 재고 전기, 고객 배송 |
| Delivery | 배송 권역→MFC 매핑, 배송 슬롯 여력, 라이더, 배차, 픽업/전달/회수 수행, 위치/ETA | 주문 취소·환불 판단, MFC 재고 |
| BackOffice | 운영자 권한, 승인 워크플로(원승인 ID 참조), 통합 사건·의무, 센터 기준정보, 감사 | 모든 거래 정본(주문·재고·결제·배차) |

## 4. 핵심 확정 정책 (설계가 바꾸지 않는 것)

| 영역 | 규칙 |
|---|---|
| 상품 | E-/B- 전역 8자리 SKU, 본사 승인 발급, E/B 합산·전환 금지, BOX/PLT는 상품 아님, 기초상품 구성 낱개 합산 상한 10개 |
| 주문 금액 | 최소 주문 15,000원(순수 상품액), 배달팁 한집 4,000/알뜰·예약 3,000, 30,000원 이상 또는 첫 구매 0원, 봉투값 주문당 100원 1회, 분할배송 추가 배달팁 없음 |
| 시간 | 가격 동결 최대 10분, 재고 예약 10분(시작 사건 다름), 00:00~08:00 실제 배송 없음(08:00 이후 슬롯 예약은 가능), 07시 도착 슬롯 없음 |
| 이행 | 지정 MFC 현물만 사용(타 MFC 재배정·합산 없음, 예정재고 예약판매 없음), 총 상품중량 10,000g 초과 시 분할배송, 피킹·포장으로 재고 불감소, 인계 시 차감 |
| 결제 | 토스페이먼츠 주문서형, 결제창 복귀만으로 승인 확정 금지, 결과 불명은 1분×5회 조회→상신→15분 간격, 부분 품절·반품은 PG 부분취소 |
| 변경·취소 | 결제 후 주소·연락처 변경 불가, 예약 시간만 `상품준비` 전 변경, 인계된 수량은 출고 전 취소 불가(회수·반품) |
| 반품 | 일반 7일, 신선 24시간, 하자·오배송·광고 상이 교환은 3개월 또는 인지 30일, 교환 왕복 9,000원(단순 변심), 회수·재배달 주소는 원주문 주소 |
| 공급 | 1요청·1이관(TRF)·1출발, 출발 후 목적지 변경·CDC 반송 없음, 승인≠확보≠출발≠수령, 공급업체 구매·ASN·MFC 간 이관은 1차 제외 |
| 주류 | 토스페이먼츠 결제 인증으로 통합, 자체 성인인증·현장 신분증/서명 없음 (Delivery 문서의 신분증 확인은 외부 참고) |
| 리뷰 | 품목별 배송완료 후 14일 이내 1건, 최초 등록 3일 후 수정 불가, 삭제 후 재작성 불가 |
| 1차 제외 | 쿠폰·프로모션·오퍼, 공급사·구매발주, CDC 외부 입고/ASN, MFC 간 이관, 예정재고 예약판매, P- SKU |

## 5. 분산 처리 공통 원칙

1. **정본은 하나.** 수량·금액·사실은 소유 서비스만 변경한다. 조회 사본·캐시·화면 표시로 성공을 확정하지 않는다.
2. **요청·사건·확정은 다르다.** 작업 요청 전송≠수락≠수행≠원장 반영≠고객 안내.
3. **타임아웃은 실패가 아니다.** 원요청·원거래·원예약을 조회하고, 확인 전에는 새 주문·새 결제·새 예약·재판매를 만들지 않는다.
4. **멱등.** `(sourceSystem, requestId)` 같은 키·같은 본문=기존 결과, 다른 본문=충돌. 이벤트는 `(sourceSystem, eventId)`로 1회 적용. 과거 사건으로 최신 상태를 되돌리지 않는다.
5. **미설정은 0/무제한/정상이 아니다.** 정책값·승인선·창이 없으면 해당 신규 실행만 보류하고 원인·담당·필요 입력을 남긴다.
6. **보상은 성공분만.** 부분 성공 시 이번 시도에서 새로 확보한 자원만 해제하고, 기존 유효 점유·이미 움직인 실물·과거 출발은 되돌리지 않는다.
