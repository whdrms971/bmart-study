# OMS 비즈니스 로직 — 상세 로직 및 운영 기준

> OMS는 **접수된 주문의 원장과 전 생명주기를 소유**하며, 결제·재고·현장 처리·배송·취소·반품·교환을 조정한다.
> Payment는 실거래 사실, WMS는 재고 원장, Delivery는 배송 수행 사실을 각각 소유한다.

## 표기 규칙

- 상태 태그: `[확정 정책]`, `[채택 설계]`, `[설계안]`, `[팀 확인 필요]` — 원문 표기를 그대로 유지한다. 명시적 결정이 없는 세부 상태와 복구 방식은 `[설계안]`으로 제시한다(1.1).
- 약어: MFC(도심 소형 풀필먼트 센터), CDC(중앙 물류센터), PG(결제대행사, 토스페이먼츠), SKU, LOT, E/B(낱개/묶음 SKU) — 정의는 `glossary.md`를 따른다.
- 용어 대응: 본문의 "센터"(예: 센터 운영 상태·센터 제한)는 원문 표기를 유지한다. glossary 기준 MFC를 가리킬 때의 다른 표기다.

## 1. OMS의 정의·하위 시스템·협업 경계

OMS는 **접수된 주문의 원장과 전 생명주기를 소유**하며, 결제·재고·현장 처리·배송·취소·반품·교환을 조정한다. Commerce가 고객 구매 여정을 담당한다면 OMS는 그 요청을 실제로 이행 가능한 주문으로 확정하고, 주문상품·이행·배송·환불 수량의 불변조건을 지켜 종료까지 추적한다. Payment는 실거래 사실, WMS는 재고 원장, Delivery는 배송 수행 사실을 각각 소유한다.

### 1.1 적용 범위와 거래·실물의 기준

OMS는 고객 주문의 접수 자격, 청구금액, 재고 확보 결과, 결제 사실, 현장 이행 및 배송 결과를 조합하여 주문을 확정·보류·취소·종결한다. 취소·교환·반품·환불의 업무 판단과 고객 약속도 담당한다.

Commerce는 고객 구매 의사와 처리 경험, WMS는 지정 MFC 재고 예약, MFC Operations는 실제 피킹·패킹·인계/슬롯, Delivery는 고객 배송 및 회수의 실제 수행·증빙, 토스페이먼츠는 실제 승인·취소 거래를 담당한다. WMS의 CDC 재고를 고객 주문에 직접 예약하지 않는다.

명시적 결정이 없는 세부 상태와 복구 방식은 아래의 `[설계안]`을 적용 대상으로 제시한다. 운영 승인이 필요한 미결정 금액·시간·권한은 설정 전 실행하지 않는다.

외부 공급업체→CDC 실제 입고·검수/구매발주는 초기 구현에서 제외하고 승인된 CDC 초기 보유부터 운영한다. 고객 반품/회수는 별도의 승인 흐름으로 처리한다.

### 1.2 하위 시스템

| 하위 시스템 | 포함하는 비즈니스 로직 |
| --- | --- |
| 주문 접수·멱등 | Commerce 주문 초안·요청키 검증, 중복 주문 방지, 접수 성공/진행/실패 처리 |
| 주문 원장·스냅샷 | 주문·주문상품 ID, 구매 수량, 구매 당시 가격·할인·배송비·봉투값·배송지·정책·동의·변경 이력 |
| 주문 확정 | 결제 승인 사실·재고 확보·배송 여력·구매 조건 검증 후 확정; 실패 시 보상 |
| 상태·생명주기 | 주문 접수·확정·준비·부분 이행·배송·완료·취소·클레임의 허용 상태 전이·종료 조건 |
| 결제 협업·대사 | 결제 승인액 대조, 결과 불명 조회, 승인 후 주문 확정 실패, 취소/환불 결과 확인 |
| 재고 확보 협업 | 주문상품별 예약 참조·해제·만료·결과 불명·재확보 처리; 재고 원장 직접 수정 금지 |
| 이행 계획·분할 | 거점·배송 방식·주문상품과 배송 단위 연결, 10kg 초과 분할 배송·부분 이행 관리 |
| 현장 준비·품절 | MFC 피킹·검품·포장 요청, 부족/파손/판매 제한 수신, 고객 동의 필요 시 보류 |
| 배송·회수 협업 | Delivery 실제 인수·전달·실패·회수, 배송 단위별 집계 |
| 전체 취소 및 정책상 허용된 부분 취소 | 전체 취소 가능 여부와 현장 경합 판정. 부분 취소는 현장 결품 시 고객의 사전 선택이 있는 경우에만 허용하고, 반품에 따른 환불은 별도 클레임으로 처리 |
| 교환·반품 | 신청·대상·사유·중복 방지, 회수·검수·교환 승인 건의 재배송·대체 이행·환불 연결 |
| 환불 의도·금액 | 원거래 스냅샷으로 환불 대상·금액 산정, 누적 부분 환불 방지, 환불 요청·결과 추적 |
| 고객·운영자 조회 | 주문상품별 취소·배송·회수·환불·교환 수량, 상태·예외·지연 조회 제공 |
| 분산 작업·복구 | 사가 단계·타임아웃·재시도·보상·대사·수동 개입·감사, 장기 미완료 탐지 |

각 행은 업무 범주이며 독립 마이크로서비스 수가 아니다. 상태의 최종 소유권·함께 확정할 수량/금액·실패 복구·운영 배포 경계를 기준으로 구현 단위를 정한다. 상위 범주에 반송·외부 입고·실제 자격 검증 등이 있어도 현재 제외된 실행을 자동 도입하지 않는다. 미설정 값은0/무제한으로 채우지 않고 영향 신규 업무만 보류한다.

### 1.3 다른 영역과의 협업

| 연계 영역 | 함께 정의할 업무 | 상대 영역이 소유하는 책임 |
| --- | --- | --- |
| Commerce | 주문 초안·확정 요청, 결제 사실 연결, 주문/클레임 상태·결과 제공 | 회원·장바구니·체크아웃·고객 경험 |
| WMS | 예약·해제·출고 중단·인계·반입·부족 결과 | 재고 원장 및 물류 수량 변경 |
| Delivery | 실제 픽업·전달·회수·실패의 주문별 수행 결과 | 라이더 인수·배송·반송의 수행 사실 |
| SCM / Replenishment | 주문 수요·품절·미이행 신호 제공 | 공급 계획; 기존 주문을 임의 변경하지 않음 |
| MFC Operations | 주문 준비·중단 요청, 피킹·포장·부족·인계 결과 | 현장 작업 배정·수행 |

상품 정본은 WMS다. 재고 예약은 OMS 요청을 WMS가 확정하고, 시간대 슬롯은 MFC Operations가 확정한다. Delivery는 라이더의 실제 인수·전달·회수 사실을 관리하는 별도 시스템이다.

직접 조회/검증 요청, 확정 사건 수신, OMS/SCM 등을 통한 간접 조율을 구분한다. 모든 시스템을 직접 호출한다고 가정하지 않으며 상대 시스템이 담당하는 기능를 복제하지 않는다. 같은 요청·사건의 재전송은 원결과를 조회하고 다른 내용을 같은 요청으로 덮어쓰지 않는다. 성공한 원장 반영과 실패한 통지/조회 갱신을 분리해 미완료 단계만 복구한다.

[확정 정책] 상품 식별은 E-낱개/B-독립 실물 묶음과 전역 공통8자리 일련번호를 사용한다. CDC/MFC는 같은 SKU를 쓰되 센터별 재고·예약·위치를 구분한다. 같은 기초상품의 구성 낱개 수 합산 기본10개 제한은 고객 구매에 적용한다. BOX/PLT는 상품이 아닌 물류 취급 단위이며 E/B포장 전환은 초기 지원하지 않는다.

### 1.4 핵심 경계·업무 결과의 판단

OMS는 고객 주문 원장·금액·이행·취소/클레임 판단을 소유한다. 재고 확보/해제·실물 수량은 WMS, 슬롯/현장 판정은 MFC Operations, 실거래는 Payment, 고객 배송·회수의 실제 수행은 Delivery가 각각 담당한다. 주문의 사업 판단과 실행 결과를 혼동하지 않는다.

요청 접수·승인·작업 배정·실제 수행·원장 반영·고객 안내는 각각 다른 결과다. 물리 수량은 센터·SKU·LOT·상태·원실물 단위로, 금액은 원거래·취소 성공/진행·잔액으로 대사한다. 타임아웃·오프라인 기록·GPS 도착·설비 완료 신호만으로 최종 실물/거래를 확정하지 않는다. 권한·최신 버전·실제 증빙·남은 의무를 확인한 뒤 업무를 종료한다.

| 주문 접수 | 회원·상품·주소·수량·가격·배송 가능성 검증 및 동일 주문 의도 식별 |
| 주문 금액 | 오퍼·행사·쿠폰 계산 결과 확정, 최소금액 및 PG 승인액 검증 |
| 이행 확보 | 지정 MFC의 전품목 예약과 필요한 시간대 확보 결과 확인 |
| 결제 | 승인·실패·결과 불명 구분, 주문 확정 또는 보상 |

## 3. 주문·자원·실거래의 상태 전이와 종결

[설계안] OMS는 주문 상태, WMS 재고 예약, MFC 슬롯/작업, Payment 승인/취소, Delivery의 고객 배송·회수 수행을 분리한다. 원초안/원주문과 단계별 요청·확정 결과를 연결하며 통신 타임아웃을 업무 실패로 확정하지 않는다.

| 현재 단계 | 진입 검증·확정 주체 | 다음 처리·완료 조건 |
|---|---|---|
| 접수/초안 | 회원·지정 MFC·E/B 구성 상한·상품/금액·주소/시간 검증 | OMS 원초안 보존, 조건 변경은 새 버전·고객 동의 |
| 자원 확보 중 | WMS 전품목 예약·MFC 슬롯/여력·쿠폰/행사 권리 | 전부 성공 후 PG진입. 일부 실패는 성공분 보상, 불명은 원점유 조회 |
| 승인 요청/불명 | Payment가 원주문·금액·원시도/PG 거래 확인 | 불명 점유 유지·정해진 후속 조회/상신. 승인 사실 전 추정 주문 확정 금지 |
| 승인 확인·주문 확정 대기 | 승인액·통화/주문·현재 확보/운영 제한 대사 | 적격 원주문 확정 복구 또는 승인된 취소 보상 |
| 확정/준비 | 주문별 이행 요청·MFC 수락/실제 준비 | 상품준비 이후 예약시간 변경 차단. 거절은 고객 약속 보존·취소/복구 판단 |
| 일부 인계/배송 | MFC/Delivery 실제 유효 포장·WMS 반영·배송별 사실 | 실제 인계분은 출고 전 취소 금지, 미인계/미배송 의무 분리 |
| 취소/클레임 처리 | 대상 수량·현장 중지/회수/검수·원안분·누적 환불 검증 | Payment 취소·자원/쿠폰 등 결과 대사 뒤 종결 |

주문 품목의 원수량은 아직 미이행으로 보유한 수량+유효 인계 누계+출고 전 취소 누계로 관리한다. 인계 후 반품은 과거 인계를 지우지 않고 별도 회수/검수/환불 수량으로 연결한다. 반품·교환·환불 진행/완료가 같은 수량을 두 번 소비하지 않도록 신청 가능량에서 기존 처리와 진행 점유를 제외한다. 재배송은 교환 승인에 따른 후속 이행으로만 허용한다. 재배송 시 원주문·교환 클레임에 연결하며 새로운 고객 구매로 중복 생성하지 않는다.

## 4. 주문 초안과 접수 검증

1. 고객의 동일 주문 의도를 식별하고 기존 초안·결제 시도·확정 주문이 있는지 확인한다. 응답 유실 후 재요청은 기존 결과를 반환한다. 같은 요청 식별자로 상품·금액·주소를 바꾸면 충돌로 거절한다.
2. 로그인 회원인지, 상품이 판매 중인지, 지정 MFC가 해당 SKU를 취급하는지, 요청 수량이 양의 정수인지 검사한다. 단품 E-와 제조사 밀봉 실물 묶음 B-는 다른 재고이며 서로 대체하지 않는다.
3. `[확정 정책]` 구매 제한은 같은 기초상품에 속한 각 SKU의 주문 수량에 구성 낱개 수를 곱한 합계로 검사한다. 기본 상한은 10개이며 상품별 승인된 예외가 우선한다. 같은 상품을 다른 카테고리나 오퍼로 나눠 담아도 합산한다.
4. 배송지의 서비스 권역, 센터 운영 상태, 작업 여력, 배송 방식, 예약 시간대 및 중량을 검사한다. 조회 실패는 재고 0이나 배송 가능으로 바꾸지 않는다.
5. 상품·규격·가격·중량·할인 배분·주소·연락처·요청 사항·품절 처리 선택과 정책 적용 기준을 주문 당시 값으로 보존한다. 고객 기본 주소나 상품 마스터 변경으로 확정 주문을 변경하지 않는다.

[확정 정책] 결제 후 주소·연락처·요청 사항은 변경할 수 없다. 예약배달에 한해 OMS 주문이 `상품준비` 상태로 진입하기 전까지 **예약 시간만** 변경할 수 있다. `상품준비`는 현장이 실제 주문 준비 시작을 확정하고 OMS가 반영하는 상태이며, 이미 준비가 시작된 사실이 확인되면 반영 지연 중에도 변경을 차단한다.

[채택 설계] 변경 시 새 시간대 정원·MFC 작업 여력·재고 예약·LOT 기한·배송 가능시간을 검증하고 새 슬롯을 임시 확보한다. 준비 시작과 시간 변경을 같은 주문에 대해 순서 판정하여 먼저 확정된 결과만 유효하게 한다. 변경 성공 후 기존 슬롯 해제·주문 버전 갱신·준비 예정/배차 제안 재계산을 수행한다. 실패하거나 준비 시작이 먼저 확정되면 새 임시 슬롯만 해제하고 기존 시간·예약·금액을 유지한다. 시간 변경을 이유로 새 결제나 중복 피킹을 생성하지 않으며 배송 방식·주소·연락처·요청 사항은 변경하지 않는다.

## 5. 가격·쿠폰·금액 확정

### 5.1 계산 순서와 구매 조건

`[확정 정책]` 기본가격 및 선택 오퍼 → 기간 프로모션 → 상품 쿠폰 → 장바구니 쿠폰 순서로 계산한다. 전사 동일 가격을 적용하며 초기 MFC별 가격 예외는 없다.

- 수량 오퍼는 고객이 명시적으로 선택해야 한다. 할인 묶음 단위로 충족한 수량에는 선택 가능한 오퍼 중 최저가 1개를 적용하고 남은 수량에는 단품 단가를 적용한다. 오퍼는 별도 실물 SKU를 만들거나 단품 재고를 B- 재고로 변환하지 않는다.
- 같은 상품의 기간 프로모션은 중첩하지 않고 할인율이 가장 높은 1개를 적용한다. 상품 쿠폰 1장과 장바구니 쿠폰 1장은 함께 사용할 수 있다. 유효기간·대상·발급/사용 한도·이미 사용 중인 권리를 검사한다.
- 정률 계산과 비례 안분의 원 미만 금액은 버린다. 장바구니 쿠폰은 대상 품목 금액에 비례 배분하고 잔여 원은 금액이 가장 큰 품목에 합산한다. `[설계안]` 최대 금액 동률은 주문 품목의 안정된 순서로 처리하며 각 품목 할인은 그 품목 금액을 넘지 않는다.
- 최소 주문금액 15,000원은 **오퍼·프로모션 후, 모든 쿠폰 적용 전 상품액**으로 판정한다. 배달팁·봉투값은 제외한다. 쿠폰 적용 후 15,000원 아래가 되어도 주문 가능하다.
- 청구액은 쿠폰 적용 후 상품액 + 확정 배달팁 + 봉투값이다. 모두 원 단위이며 음수 청구를 허용하지 않는다. 포인트·선물 잔액·자체 간편결제는 참고 화면만으로 도입하지 않는다.

### 5.2 부대비용과 혜택

`[확정 정책]` 봉투값은 미사용 선택이나 분할배송 여부와 관계없이 주문당 100원 1회다. 전체 취소 시 전액 환불하며 단순 변심 부분 취소에는 환불하지 않는다. 10kg 초과 분할배송으로 배달팁을 추가 청구하지 않는다.

첫 구매는 최종 결제 확인·주문 확정 이력이 없는 계정이다. 실패·타임아웃 취소·결제 직후 출고 전 전체 취소는 첫 구매 자격을 소진하지 않는다. 첫 구매 배달팁은 무료이며 배송 쿠폰과 중복 차감하지 않고 더 유리한 혜택 하나를 적용한다. `[설계안]` 같은 계정의 동시 주문은 혜택 권리를 점유하여 중복 사용을 막고, 취소 결과에 따라 복구한다.

[확정 정책] 한집배달은4,000원, 알뜰배달·예약배달은3,000원이다. 상품금액30,000원 이상 또는 첫 구매이면 배달팁0원이며 주문당 봉투값100원은 유지한다. 분할배송으로 배달팁을 추가하지 않는다. [채택 설계] 30,000원 판정 상품액은 최소 주문금액과 같이 오퍼·프로모션 후, 쿠폰 전 금액으로 통일한다.

### 5.3 가격 동결

가격과 쿠폰 적용 상태는 결제 페이지에서 주문서 초안을 생성한 시점부터 최대 10분간 동결한다. 기간 내 일반 가격·행사 변경은 초안에 소급하지 않는다. 10분 경과 후에는 최신 금액과 혜택으로 재계산하고 고객 재확인을 받는다. 재고 적격성·리콜·사용 권한 검증은 가격 동결과 관계없이 계속 수행한다.

가격 유효시간과 재고 예약 10분은 서로 다른 시작 사건이다. `[설계안]` PG 진입 전 둘 다 유효한지 확인하고 더 이른 만료를 고객에게 안내한다. 결제 결과 불명 상태에서는 새 가격으로 별도 결제를 만들지 않는다.

### 5.4 쿠폰 권리·행사 한도와 재고 확보

[설계안] OMS는 쿠폰의 대상 계정·유효기간·조건·중복·제한 상태를 검사해 주문별 사용 대기를 요청한다. 쿠폰의 동시 중복 사용을 차단하고 OMS가 결제 승인 및 주문 확정을 확인한 뒤 사용을 확정한다. 응답 유실은 같은 점유/사용 결과를 조회하고 중복 사용하지 않는다. 결제/주문이 확정되지 않았다고 즉시 쿠폰을 풀지 않으며 PG 미승인·실패·취소가 확인된 건만 해제한다. 늦은 승인/주문 저장 실패/PG불명은 재고·쿠폰·행사 점유를 유지한 채 복구/원거래취소를 대사한다.

행사 한도는 OMS가 승인된 정책 범위에서 관리하는 할인 권리이며 CDC/MFC 현물·재고 예약은 WMS가 주관한다. PG 진입 전 현재 행사 잔여량과 전품목 재고 예약을 모두 확보한다. 쿠폰·행사·재고 중 일부 성공 후 나머지 실패이면 PG를 차단하고 성공분 보상 해제를 확인한다. 중간 응답 불명은 원점유를 조회해 확정 전 재사용하지 않는다. 마지막1개 경합은 예약 성공 주문만 결제에 진입하며 결제 완료 순으로 승자를 다시 바꾸지 않는다. 가격 초안만으로 행사 물량은 확보되지 않는다.

행사 미사용 한도 = 승인 총한도 − 사용 확정량 − 유효 점유량이며 모두 해당 SKU 판매 단위 개수다. 과거 한도 감액으로 음수이면 신규 점유는0으로 막고 기존 점유를 임의 취소하지 않는다. 결제 승인·주문 확정 시 같은 행사 점유를 사용 확정으로 한 번 전환하고 현물 차감은 계속 실제 인계를 기다린다. 실패/미승인/취소가 확인된 미확정 주문의 점유는 해제한다. 주문 확정 후 취소/반품은 사용 실적을 삭제하지 않고 한도 복구 여부 미결정으로 별도 보류한다. 행사 종료는 기존 유효 점유의 가격 약속을 취소하지 않지만 신규 초안/점유에는 종료 상태를 적용한다.

기본가격/오퍼→기간 행사 최고 할인율1개→쿠폰의 확정 계산 순서를 유지한다. 유효한10분 초안의 일반 행사 가격은 유지하고 초안 만료 후 재견적한다. 신규 쿠폰 사용 점유는 권리 만료·남용 제한을 계속 검증하며 유효한 점유 없이 할인 적용만 동결해 PG를 진행하지 않는다. [팀 확인 필요] 쿠폰 유효기간을 넘는 진행 결제·PG 지연의 권리 보장/보상과 행사 취소/반품분 한도 재개는 미결정이다. 기준 미등록 권리 재개·새 할인을 자동 부여하지 않는다.

[설계안] 승인된 LOT 한정 할인 주문은 고객이 동의한 허용 LOT/기한 조건과 금액을 함께 보존해 MFC Operations에 전달한다. 해당 후보 안에서 단일LOT 우선/최대2LOT와 안전량을 검사한다. 할인 LOT가 소진됐다고 정상가 LOT를 자동 증액 대체하지 않는다. 적격 동일 조건 재확보가 불가능하면 고객 품절 선택과 취소/환불로 처리한다. 다른 상품/정상가 재구매는 고객 동의와 새 견적으로 진행한다. [팀 확인 필요] 허용 LOT 범위·복수 기한 표시가 승인되지 않은 마감 판매는 확정하지 않는다.

## 6. MFC 배정·예약·시간대 확보

`[확정 정책]` 배송지에 지정된 MFC의 재고만 사용한다. 초기 다른 MFC 자동 재배정과 여러 MFC의 재고 합산 이행은 지원하지 않는다. 동일 MFC에서 나누는 중량 분할배송은 허용한다.

WMS가 제공한 지정 MFC 정상 보유량에서 유효 예약과 안전재고를 뺀 판매 예약 가능량을 기준으로 전품목 예약을 요청한다. 현물 조회만으로 확보를 선언하지 않는다. 장바구니는 예약하지 않으며 **주문 초안의 PG 진입 직전** 재고를 확보한다. 다품목은 전부 성공해야 결제를 시작하고 일부만 성공하면 성공분 해제를 확인한다.

예약은 10분 유효하다. 결제 확인 후에는 이행 예약을 유지하고 피킹만으로 현물을 차감하지 않는다. 필요한 예약 배송 슬롯도 재고와 별개로 확보한다. 슬롯 실패 시 재고 예약을 해제하고 결제를 시작하지 않는다. 슬롯 정원은 MFC 작업·패킹·보관 여력과 Delivery의 고객 배송 가능 조건 중 승인된 조건을 만족해야 한다.

[채택 설계] 예약 주문도 현재 지정 MFC 적격 현물과 WMS 예약 권리만 사용한다. 예정재고 예약판매는 초기 구현에서 제외하며 SCM 공급 예정은 계획 계산에만 사용한다. 이를 추가 계약 대기 상태의 판매 허용 기능으로 표현하지 않는다.

주류 포함 주문은 토스페이먼츠 결제 인증 결과를 확인하고 별도 자체 성인인증·현장 신분증/서명 절차를 요구하지 않는다. 인증 성공만으로 PG 승인·주문 확정을 대체하지 않는다.

[확정 정책] 00:00 이상08:00 미만에는 고객 대상 실제 배송을 제공하지 않는다. 이 시간에도08:00 이후의 실제 제공 가능한 시간대를 선택해 예약 주문·결제할 수 있다. 07시 도착 슬롯은 제공하지 않는다. MFC·라이더의08시/09시 개시 차이와 시간대별 정원은 남은 확인 사항이며, 실제 가용 조건을 모두 충족하는 슬롯만 판매한다.

### 6.1 예약 슬롯과 미설정 조건

[채택 설계] 주문 접수 시간과 실제 준비/배송 시간을 구분한다. 신규 예약은 미래 슬롯의 승인 정원·MFC 준비/인계 시간·Delivery의 고객 배송 가능 조건·현재 적격 현물·예정 출고 기한을 모두 검증한다. 현재 MFC 영업 종료만으로 미래 예약을 일괄 거절하지 않으며 심야 실제 배송 금지는 유지한다.

슬롯 정원·점유의 정본은 MFC Operations이며 OMS는 주문별 확보·확정·해제·변경을 요청한다. OMS의 조회용 잔여 정원만으로 확보 성공을 선언하거나 현장과 별도 소진하지 않는다. 같은 주문 요청의 중복 전송은 같은 슬롯 점유 결과를 조회한다.

슬롯 승인 상한에서 확정/진행 중 유효 주문 점유를 빼고 주문당1건을 확보한다. 같은 주문의 분할배송은 슬롯1건으로 관리하며, 고객 배송 수행 가능 여부는 Delivery의 운영 조건에 따라 별도 확인한다. 마지막 정원1건은 한 주문에만 확보하고 결제/변경 실패가 확인된 점유만 해제한다. 조회 실패·미설정은 정원0 또는 무제한이 아닌 확인 대기로 처리해 해당 신규 결제를 막는다. 시간 변경은 새 슬롯/기한 검증·준비 시작 경합 판정 성공 후 기존 점유를 해제한다. 정원 축소·운영시간 변경은 기존 주문 약속을 삭제하지 않고 영향 주문의 이행 가능성·고객 대응을 조사한다.

## 7. 결제·주문 확정·만료 복구

`[확정 정책]` 토스페이먼츠 주문서형을 사용한다. 결제창 복귀나 고객앱 성공 표시로 승인 사실을 확정하지 않는다.

| 확인 결과 | OMS 처리 |
|---|---|
| 원거래·주문·원화 금액 일치, 승인 성공, 예약 유효 | 결제 확인 → 주문 확정 → 동일 이행 건으로 현장 요청 |
| 승인 실패 확정 | 주문 미확정 유지, 재고/슬롯 해제 확인, 재시도 안내 |
| 승인 결과 불명·통신 오류 | 결제 확인 중, 원거래 조회, 신규 승인/중복 결제 금지 |
| 승인 성공이나 주문 저장/이행 연결 실패 | 원거래를 복원해 연결하거나 취소 보상 검토, 임의 새 주문/재승인 금지 |
| 금액·통화·주문 불일치 | 확정 차단, 거래 대사와 적법한 보상, 강제 출고 금지 |
| 예약 소멸 후 지연 승인 | 현장 이행 차단, 재확보 가능성 확인 후 복구 또는 승인 취소 |

[채택 설계] 결제 전 일반 예약은10분 유효하다. 만료 시 원거래를 조회하여 미승인/실패 확정이면 재고·슬롯을 해제하고 주문을 만료 처리한다. 만료 후 승인 성공이 확인되면 기존 이행 권리와 고객 약속을 복구할 수 있는지 재검증하고, 불가능하면 동일 원거래 승인취소를 요청한다. 승인취소 성공 전에는 재고를 재판매하지 않는다.

조회/취소 결과가 불명이면 일반 예약을 `결제 확인 대기 점유`로 전환하여 신규 이행·재결제·재판매를 막는다. 만료 직후 조회에 이어1분 간격으로 최대5회 재조회한다. 끝까지 불명이면 OMS/결제 운영 담당의 확인 사건으로 상신하고15분 간격 후속 조회를 유지한다. 시간 경과만으로 자동 해제하지 않으며, 수동 종결도 PG 원거래의 미승인·실패·취소 또는 적격 주문 복구 증거를 확인해야 한다. 중복/지연 결과는 같은 원거래와 점유에 한 번만 반영한다.

중복 승인 결과는 원거래별 한 번 반영한다. 승인 성공·주문 저장 실패로 주문번호가 없는 경우에도 영속 결제시도와 검증된 원거래로 조사한다. 금액·시간만 비슷한 다른 주문에 임의 연결하지 않는다. 승인과 취소가 경합하면 PG 최종 거래와 예약 상태를 대사한 후 한 결과만 확정한다.

[채택 설계] 품질·LOT 배정은 MFC Operations가 주관한다. 신규 예약과 시간 변경은 현재 판매 기준 및 예정 출고일의 출고 기준까지 통과해야 한다. 고객 품목행은 단일 적격 LOT 충족 우선이며 불가능할 때만 최대2LOT를 사용한다. 3LOT 필요는 품절이 확정됐다는 뜻과 구분해 작업 보류로 받고 재계수/재배정 결과를 기다린다. 대체 실패는 고객 품절 선택과 부분 품절 PG부분취소/전체 취소로 연결한다. 품목행 분할로 LOT 제한을 우회하거나 같은 주문을 재결제하지 않는다.

## 8. 피킹·결품·취소 조정

### 8.1 이행 요청과 거절

확정 주문·유효 예약·미취소 상태를 확인해 MFC Operations에 이행을 요청한다. 수락은 작업 접수이며 피킹·패킹·인계 완료가 아니다. 같은 이행 요청을 재전달해도 작업을 중복 생성하지 않는다.

재고 불일치, LOT 부적격, 운영 중단, 처리 여력 부족으로 거절되면 원천 사실과 잔존 예약을 확인한다. 같은 MFC 내 적격 재고 복구가 가능하면 새 작업 버전으로 재개한다. 불가능하면 고객 선택에 따라 보류 또는 취소·금액 정산을 진행한다. 다른 MFC 자동 재배정이나 실물 묶음 대체로 우회하지 않는다.

### 8.2 피킹 결품

주문 당시 고객은 `품절 상품만 취소` 또는 `전체 취소`를 선택한다. 결품 보고를 받으면 실제 부족량, 진행 중 작업, 이미 인계한 수량과 선택을 대조한다. 유효한 사전 동의가 있으면 그 범위에서 주문 변경을 진행하고 없거나 적용 여부가 불명하면 출하를 보류해 고객센터로 이관한다. 임의 대체 상품 출고는 허용하지 않는다. 부분 처리 시 남은 주문의 최소금액이 15,000원 미만이어도 이미 승인된 주문은 유지한다.

### 8.3 취소와 인계 경합

`[설계안]` 피킹 전에는 현장 작업 중지와 예약 해제를 확인해 일반 취소를 진행한다. 피킹·패킹 이후 인계 전에는 해당 수량을 보류하고 실물 복귀·검수 결과를 확인한다. 취소 접수만으로 예약을 판매 가능 상태로 풀지 않는다. 라이더에게 실제 넘긴 수량은 출고 전 취소 대상에서 제외하고 회수·반품 절차로 처리한다. 정확한 고객 자율 취소 마감과 CS 승인선은 팀 확정이 필요하다.

취소와 인계는 동일 수량에 대해 한쪽 결과를 먼저 확정하고 후속 요청은 최신 상태로 재심사한다. 작업 중지 응답 유실은 결과 조회를 우선한다. 취소 완료·환불 완료·재고 복구는 각각 별도다.

### 8.4 취소 접수와 현장 중지·인계 판정의 분리

[채택 설계] OMS는 취소의 사업상 가능 여부를 심사하고 MFC Operations가 포장/구성 수량별 출고 중지 또는 실제 인계를 최종 확정한다. 취소 요청의 접수시각만으로 인계보다 우선했다고 판단하지 않는다. 먼저 현장에서 출고 중지가 확정됐으면 신규 인계를 막고 복귀/검수·예약 해제 결과를 확인한다. 인계 진행이면 취소 요청은 `인계 확인 중`으로 두고 결과를 기다린다. 실제 인계 확정량은 출고 전 취소하지 않고 회수/반품으로 안내한다.

취소 요청 처리 상태는 접수→출고 중지 확인 중/인계 확인 중→취소 처리 중→취소 완료 또는 취소 불가로 구분한다. 이는 주문의 상품준비/배송 상태와 별도다. 현장 응답 불명은 같은 요청의 포장별 판정 결과를 조회하며 신규 취소·환불·예약 해제를 반복하지 않는다. 현장 중지와 재고 복귀가 끝나도 PG 취소 성공 전에는 환불 완료로 안내하지 않는다. PG불명은 기존 결과 확인 절차를 따른다.

일부 포장 인계 시 인계량·미인계량·중지 가능량을 분리해 유효 주문 수량과 대사한다. 이미 인계된 수량까지 전체 취소/전체 재고 복구하지 않는다. 미인계분의 취소는 기존 사유/권한·부분 품절 범위로 심사하고 고객 임의 부분 취소 정책을 확대하지 않는다. 고객 배송 수행이 이미 시작된 경우에는 Delivery의 실제 인수 상태를 확인해 후속 의무를 판단한다.

### 8.5 품절 시점별 부분 유지·포장·PG 취소

PG 전 품절은 견적/선택 변경·고객 동의와 부분 성공 확보 해제로 처리한다. 승인 뒤 품절은 원결제의 해당 원가격/원안분 취소와 고객의 유효한 품절 선택으로 남은 이행을 판단한다. 잔여15,000원 미만을 이유로 재결제를 강요하거나 미승인 배달팁을 추가하지 않는다. 피킹/패킹 진행 중이면 MFC가 준비·부족·중지·유효 포장을 확정하고 WMS가 적격 대체·예약을 처리한다. 고객이 선택하지 않은 SKU/기한 조건으로 자동 대체하지 않는다.

인계 선확정 또는 불명은 출고 전 취소/재고 해제를 보류하고 실제 포장별 사실을 대사한다. 일부 인계이면 인계량과 미인계량을 나눠 판단한다. MFC의 포장 재구성 뒤 새 유효 수량/버전만 출고에 허용하고 무효 라벨의 늦은 스캔을 차단한다.

## 9. 분할배송과 배송 결과

총 상품중량은 각 SKU의 주문 수량 × 판매 단위중량을 전부 더한 값이며 단위는 g이다. **10,000g 초과**이면 최소 2개 배송으로 나누고 각 배송의 상품중량을 10,000g 이하로 배정한다. 정확히 10,000g은 이 규칙에 의한 분할 대상이 아니다. 주문·PG 결제·봉투값은 각각 1건/1회로 유지한다.

품목별 배송 배정 수량의 합계는 주문의 유효 이행 수량과 같아야 한다. 포장과 배송은 서로 다르므로 포장 수를 그대로 결제나 배송 횟수로 계산하지 않는다. 고객 배송 수단별 중량·부피·봉투 및 보냉 조건은 고객 배송 운영 기준에서 검증한다. 단일 상품 1개가 10kg 초과이거나 중량이 없으면 임의 분할하지 않고 해당 주문 확정을 보류한다. 허용 상품/수단과 포장재 중량 포함 기준은 팀 확인이 필요하다.

모든 유효 배송이 전달 완료되어야 주문 전체 배송완료다. 일부 완료는 부분 전달이며 미전달 수량이 환불·취소로 해소되면 배송완료와 구분한 이행 종결로 관리한다. 배송 실패는 원배송에 연결해 기록하고, 지연·수행 실패만으로 자동 환불하지 않는다. 고객 연락, 보관 가능성, Delivery를 통한 후속 조치·회수 여부를 판단하며 재배송은 교환 승인 건에 한해 허용한다. 고객 수령 사실이 없는 시간 경과 자동완료는 수행하지 않는다.

## 10. 환불 금액과 결제 실행의 경계

환불 기준은 원주문 가격 스냅샷과 품목별 할인 배분이다. 이미 확정한 가격을 현재 가격으로 다시 계산하거나 할인 전 금액을 환불하지 않는다. 부분 취소의 상품 쿠폰은 기존 소멸 기준을 따르고 장바구니 쿠폰은 원안분 금액으로 정산한다. 전체 취소의 복원 자격·유효기간은 아래 기본안과 미결정 사항을 구분한다. 부분 쿠폰 복원의 구체 방식과 배송비 환수 조건은 팀 확인 전 자동 적용하지 않는다.

추가 환불 가능 한도(원) = 최초 승인액 − 성공한 누적 환불액 − 결과 미확정/처리 중 환불 점유액이다. 이 한도와 실제 승인된 환불 사유의 금액 중 작은 금액까지만 요청할 수 있다. 같은 품목 수량에 취소·반품·미배송 환불을 중복 부여하지 않는다.

[확정 정책] 부분 품절·반품에 대해서는 원결제의 해당 상품·수량 금액에 대한 **부분 결제취소를 지원**한다. 원주문 가격·할인 안분으로 취소액을 산정하고 이미 성공했거나 처리 중인 취소액을 제외한 잔액 한도 내에서 토스페이먼츠에 요청한다. 전체 취소 후 잔여 상품 재결제를 기본 처리로 사용하지 않는다.

부분 품절은 사전 동의한 품절 처리 선택과 현장 중지 결과, 반품은 접수 자격·승인·정책상 검수 결과를 확인한 뒤 요청한다. 성공 시 해당 품목의 취소/환불량과 결제 잔액을 함께 갱신하며 나머지 주문은 유지한다. PG 응답 불명은 원거래를 조회하고 같은 취소 요청의 결과를 확인하며 새 요청으로 중복 차감하지 않는다. 고객의 임의 부분 취소나 기타 사유까지 이 지원 범위를 자동 확대하지 않는다.

환불은 `접수 → 심사/승인 → 실행 대기 → PG 결과 확인 → 완료/실패/확인 중`으로 구분한다. 승인만으로 완료하지 않는다. 응답 유실은 같은 거래 조회·같은 환불 요청 재처리를 사용하고 새 금액취소를 중복 실행하지 않는다.

### 10.1 취소 확정과 쿠폰 복원·추가 정산 경계

[설계안] 전체 취소와 원결제 취소 성공을 확인한 시각에 동일 쿠폰의 원래 사용 유효기간이 남아 있으면 쿠폰 복원을 한 번 요청한다. 복원은 기존 만료시각을 연장하거나 새 쿠폰을 발급하지 않는다. 기간이 지났으면 만료로 기록한다. PG 결과 불명/환불 진행 중에는 먼저 쿠폰을 돌려주지 않는다. 발급 기간 종료와 사용 유효기간 만료는 다르므로 발급 행사가 끝났다는 이유만으로 유효 쿠폰 복원을 거절하지 않는다. 결제 미승인/실패가 확인된 사용 대기 해제도 현재 기간/제한 상태를 재검증한다.

[팀 확인 필요] 정책별 복원 금지 예외, 전체취소 접수는 기간 내였으나 PG 확정이 만료 뒤인 건의 보상, 부분 품절/반품으로 쿠폰 최소금액/무료배송 기준이 깨진 경우 할인·배달팁 환수와 쿠폰 재발급은 미결정이다. 기본 환불은 원가격·원안분과 확정 배달팁 기준을 유지하며 임의 추가 청구·현재 가격 재계산·미승인 할인 환수는 하지 않는다. 정책 심사가 필요한 건은 담당자에게 연결하되 이미 확정된 부분 품절/반품 PG부분취소 지원 자체를 미지원으로 바꾸지 않는다. 쿠폰 복원 실패는 환불 결과를 되돌리지 않고 별도 복원 대기로 조회/재처리한다.

### 10.2 원결제 안분·첫 구매와 누적 환불 검증

정률/안분 원 미만 버림·대상 최대금액 품목에 잔여 원 배분이라는 원기준을 유지한다. A20,000/B10,000·쿠폰3,000·무료배송·봉투100이면 원결제27,100, B원안분 환불9,000, 잔액18,100이다. PG 누적 성공/진행·불명 금액을 제외한 잔액만 새 취소할 수 있다. 단위 수량 일부 환불의 추가 원 단위 배분·조건부 쿠폰 환수 등 미정 부분은 승인 심사로 분리한다.

## 11. 반품·교환·회수

### 11.1 접수와 자격

고객센터가 원주문·배송 건·품목·수량·사유·사진·기존 접수/환불을 확인한다. 미배송은 실제 수령품 반품과 구분한다. 반품 가능 수량은 실제 전달량에서 완료/진행 반품 점유량을 뺀 범위다.

[확정 정책] 일반 교환·반품은 해당 상품의 실제 수령 후7일 이내, 신선식품(냉장/냉동)은 수령 후24시간 이내 접수한다. 하자·오배송·광고 내용과 다른 상품의 **교환**은 수령 후3개월 이내 또는 그 사실을 안 날(알 수 있었던 날)부터30일 이내 조건 중 하나를 충족하면 심사한다. 이 교환 사유에는 일반7일/신선24시간 제한을 우선 적용해 거절하지 않는다. 증빙과 수령·인지 시점을 확인하며 접수 자격과 최종 승인·환불 완료는 구분한다.

[채택 설계] 기한은 Asia/Seoul 기준 실제 수령시각에서 계산하고 경계시각까지 접수 가능하다. 3개월은90일로 치환하지 않고 달력상3개월로 계산하며 해당 일이 없는 달은 말일을 사용한다. 분할배송은 신청 대상 상품의 실제 수령시각을 기준으로 한다. 인지/인지 가능 시각이 불명확하면 증빙 보완 심사로 넘긴다. 특례의 반품 적용 범위와 증빙 필수 기준은 별도 확인 대상으로 남긴다.

[확정 정책] 회수·재배달 주소는 원주문 주소로 고정한다. 교환은 배송완료 후 신청 전체에 같은 사유를 적용하며 동일 주문 중복 교환을 막는다. 신선식품도24시간 접수 기준으로 심사하고, 상품 하자·오배송·광고 상이 교환에는3개월/인지30일 특례를 적용한다. 단순 변심 교환 왕복 비용은 합계9,000원, 상품/배달 문제는 구매자 부담0원이다. 왕복 운송을 각각9,000원으로 계산하지 않는다.

교환 왕복 배달비9,000원과 상품 환불액을 별도 관리한다. 일반 반품 회수비는 별도 부과/환급 정책을 확인하며 교환 비용을 자동 전용하지 않는다. 회수비 결제만으로 상품 반품 승인·환불 완료로 처리하지 않는다. 거절·미회수 시 비용 환급과 수납 방식은 남은 확인 사항이다.

### 11.2 실행과 재고 영향

1. 회수 대상과 필요 여부를 승인하고 Delivery에 원주문과 연결된 회수 작업을 요청한다. 고객 수거·MFC 반납·MFC Operations 수령·검수는 별도 결과다.
2. 회수 없는 처리에는 승인 사유와 증빙을 남긴다. 기본 회수 원칙의 예외이므로 승인 없이 단계를 생략하지 않는다.
3. 반품 검수 결과와 실제 지급액을 근거로 환불을 진행한다. 정확한 환불 개시점은 회수 확인/센터 수령/검수 완료 중 팀 정책을 등록해야 한다. `[설계안]` 미설정이면 심사 대기 후 담당자에게 상신하며 자동 환불하지 않는다.
4. 교환은 대체 상품 재고를 별도 확보하고 새 피킹·패킹·배송을 생성한다. 원배송 이력을 지우지 않는다. 교환품 품절은 고객과 환불 또는 대기 방식을 협의하며 자동 대체하지 않는다.
5. 환불·회수 요청만으로 재고를 복구하지 않는다. 상온 미개봉 적격품만 현장 검수 후 복구하고 신선·냉장·냉동 회수품은 재판매하지 않는다. 교환 승인에 따른 교환품 출고는 새 출고 수량만 한 번 차감한다.

### 11.3 클레임 일부 승인·회수 차이·철회

[설계안] 신청 사건과 품목별 심사·회수·검수·환불/교환 이행을 구분한다. 3개 신청 중2개 승인/1개 거절이면2개만 후속 작업으로 보내고1개 사유·증빙·안내를 유지한다. 회수 승인량보다 적게 수거/반납되면 미수거/미반납을 남기고 검수/PG 결과를 선완료하지 않는다. 교환품 품절은 고객 동의와 승인된 환불 전환을 심사하며 무단 상품 변경·무기한 대기를 기본 처리하지 않는다.

[팀 확인 필요] 철회 가능 단계, 실제 회수 뒤 철회 비용, 일반 반품비·환불 개시점·거절품 재전달은 사업 승인 대상이다. 철회 요청은 이미 진행한 Delivery 실제 수행·현장 실물·Payment 취소를 대사해 처리하고 사건 삭제로 미결 의무를 없애지 않는다.

## 12. 정합성·권한·운영 재개

- 유효 주문 수량은 인계량 + 출고 전 확정 취소량 + 미인계 잔량으로 대사한다. 같은 수량을 취소와 인계에 함께 넣지 않는다. 반품은 이미 인계된 물량의 후속 사건이다.
- 원장 변경과 고객 통지를 분리한다. 알림 실패는 통지만 복구하고 주문·결제·현장 작업을 재생성하지 않는다.
- 지연·중복·역순 이벤트는 원천 최신 상태와 정정 이력으로 판단한다. 완료 후 과거 피킹 이벤트로 상태를 되돌리지 않는다.
- CS 요청·승인·PG 실행 권한을 구분하고 고액/예외 보상 승인선은 설정 전 자동 허용하지 않는다. 개인정보는 담당 주문 범위에서 최소 노출한다.
- 영업 종료·장애·리콜이 발생해도 기존 결제·재고·배송 의무를 삭제하지 않는다. 담당자, 현재 상품 위치, 미확정 금액, 다음 조치와 확인 시각을 인계한다.

## 13. 운영 제한·탈퇴·재고 예외의 연계 계약

[채택 설계] MFC 운영 제한 정본은 MFC Operations, CDC는 WMS다. OMS는 주문 확정·예약시간 변경·상품준비 시작 시 지정 MFC의 최신 업무별 제한과 Delivery의 고객 배송 가능 조건을 함께 검사한다. 제한과 진행 요청 경합은 주관 시스템의 확정 순서로 판정한다. 접수 중지만으로 기존 주문을 취소하지 않으며 안전 작업 중지는 영향 주문 준비를 보류해 실제 미인계 수량·고객 약속을 조사한다. 정본 조회 불명은 해당 신규 처리를 보류한다.

Commerce 탈퇴 접수 이후 신규 주문을 막되 이전 결제·배송·교환·환불·분쟁은 기존 주문으로 이행한다. 결제 불명/미결 의무가 있으면 탈퇴 완료 불가를 회신하고 의무 종결 후 Commerce가 재조회한다. 탈퇴는 재고 해제/결제취소 명령이 아니다. 완료 후 보존 증빙은 업무 권한으로만 조회하며 재가입 계정에 자동 연결하지 않는다.

예정재고 예약판매는 초기 구현에서 제외한다. 예약배달도 현재 지정 MFC 품질·적치·판매 준비를 통과한 현물만 확보한다. SCM ETA 확정을 이유로 없는 재고의 결제/약속을 먼저 만들지 않는다.

예약 LOT 보류 시 WMS가 BLOCKED 수량·대체 확보 결과를 회신하고 MFC Operations는 해당 현장 작업을 차단한다. OMS는 미이행 약속을 보존하되 피킹/인계를 차단하고 안전재고·타MFC·예정 재고로 우회하지 않는다. 성공은 같은 주문 예약 갱신이며 재결제하지 않는다. 실패는 고객 품절 선택과 부분 품절 PG부분취소/전체 취소 정책으로 처리하며 미확정 부분은 담당자 심사로 넘긴다. PG불명 확인대기와 겹치면 품질 차단은 즉시 적용하되 결제 확인 전 점유를 단순 해제하지 않는다.

### A.1 OMS 내부 업무 모듈의 구조와 책임

OMS의 하위 시스템은 주문 생명주기의 업무 책임을 나누어 설명하기 위한 논리적 모듈이다. 아래의 모듈이 반드시 각각 독립된 마이크로서비스나 별도 배포 단위라는 뜻은 아니다. 실제 서비스 경계는 원장 소유권, 수량·금액을 함께 확정해야 하는지, 장애 시 보상 방식, 운영 배포 경계를 기준으로 결정한다.

#### A.1.1 주문 접수·요청 멱등 처리

**책임과 목적**

Commerce에서 전달한 주문 초안 생성·확정 요청을 접수하고, 요청이 신규 주문 의도인지 기존 요청의 재전송인지 판별한다. 네트워크 재시도나 응답 유실 때문에 동일 고객 주문이 두 번 생성되거나 결제 절차가 중복 실행되지 않도록 한다.

**입력 및 검증**

- 고객·계정 식별자와 요청 권한 정보
- Commerce 요청 식별자 및 멱등성 키
- 상품 SKU, 주문 수량, 선택 오퍼, 쿠폰 참조
- 지정 MFC, 배송지, 배송 방식, 예약 시간, 고객의 품절 처리 선택
- 요청에 포함된 주문 버전 또는 초안 참조

같은 멱등성 키로 다시 요청된 경우 기존 요청의 핵심 입력값과 요청 내용을 비교한다. 내용이 같으면 기존 처리 결과 또는 현재 진행 상태를 반환한다. 같은 키인데 상품·수량·금액·배송지 등 핵심 입력이 다르면 기존 요청을 덮어쓰지 않고 충돌로 거절한다.

**처리 결과**

- 신규 요청 접수 및 초안 식별자 반환
- 기존 요청의 처리 결과 반환
- 기존 요청 진행 상태 반환
- 입력 충돌, 권한 오류, 검증 거절 및 재시도 가능 여부 반환

**연계·복구 경계**

Commerce가 응답을 받지 못했다는 이유만으로 새 주문을 생성하지 않는다. OMS는 기존 요청을 조회해 원결과를 반환해야 한다. 주문 접수 단계의 성공은 결제 승인이나 주문 확정을 의미하지 않는다.

#### A.1.2 주문 원장·주문상품 원장·불변 스냅샷

**책임과 목적**

OMS는 접수된 고객 주문의 원장과 주문 생명주기를 소유한다. 주문 전체와 각 주문상품을 구분하고, 주문 당시의 조건 및 이후 발생한 상태 변화를 추적한다.

**보존 데이터 범주**

- 주문 ID, 주문상품 ID, 고객·계정 참조, 주문 버전
- SKU, 상품 표시명·규격, 수량, 구성 낱개 수 등 주문 당시 상품 정보
- 기본가격, 선택 오퍼, 행사 할인, 상품 쿠폰, 장바구니 쿠폰, 품목별 할인 배분
- 상품액, 배달팁, 봉투값, 청구액, 통화, 결제 시도 및 PG 거래 참조
- 배송지·연락처·배송 방식·예약 시간·요청 사항
- 주문 당시 적용된 정책 버전, 고객 동의, 품절 처리 선택
- 재고 예약, 슬롯 점유, 현장 이행, 배송, 취소, 교환·반품·환불 참조
- 상태 변경 시각, 요청 식별자, 변경 사유, 연계 결과 및 감사 추적 정보

**처리 규칙**

확정된 주문의 과거 조건은 고객 기본 주소, 상품 마스터, 행사 정책 등이 이후 변경되어도 덮어쓰지 않는다. 허용된 주문 변경은 변경 전후 버전과 사유를 남긴다. 예약 시간 변경과 같이 허용된 변경도 기존 스냅샷을 지우는 방식이 아니라 새 버전 및 변경 이력으로 추적한다.

**소유권 경계**

OMS 원장은 고객 주문과 주문 의무를 기록한다. PG의 실제 승인·취소 사실, WMS의 재고·실물 수량, MFC의 현장 수행 사실, Delivery의 실제 수행 증빙은 각각 해당 소유 시스템의 결과를 참조한다.

#### A.1.3 주문 검증·금액 확정 모듈

**책임과 목적**

주문 접수 시점과 결제 진입 직전에 주문이 판매·이행 가능한 조건인지 검증하고, 고객에게 청구할 금액 및 주문 당시 적용된 할인 근거를 확정한다.

**검증 항목**

- 로그인 회원 및 주문 요청 권한
- 상품 판매 상태, 지정 MFC 취급 가능 여부, SKU·수량 형식
- 같은 기초상품에 대한 E-/B- 구성 낱개 수량 합산 구매 상한
- 서비스 권역, 센터 운영 제한, 배송 방식, 예약 시간대, 주문 중량
- 기본가격·선택 오퍼·기간 프로모션·상품 쿠폰·장바구니 쿠폰 계산 순서
- 최소 주문금액, 배달팁, 봉투값, 첫 구매 혜택 및 쿠폰·행사 권리
- 가격 초안 유효시간과 재고 예약 유효시간
- 결제 진입 직전의 가격·혜택·자원 적격성

**처리 결과**

검증 성공, 고객 입력 수정 필요, 판매 불가, 정책상 제한, 자원 확보 대기, 가격 재확인 필요, 결제 진입 가능 등의 결과를 구분한다. 조회 실패나 설정 누락을 재고 0, 무제한, 배송 가능 등으로 추정하지 않는다.

**연계 경계**

상품·재고 원장 자체를 OMS가 임의로 수정하지 않는다. OMS는 해당 소유 시스템의 최신 사실을 검증하고 주문 판단에 사용한다. 실제 승인액이 OMS의 확정 청구액과 다르면 주문 확정을 차단하고 대사 대상으로 남긴다.

#### A.1.4 주문 확정 조정 모듈

**책임과 목적**

결제 승인, 재고 예약, 필요한 배송 슬롯, 가격·구매 조건 등 서로 다른 시스템에서 확정되는 사실을 결합해 고객 주문을 확정할 수 있는지 판단한다.

**진입 조건**

- 주문 초안과 핵심 입력이 유효함
- 적용 가격·쿠폰·행사 권리가 유효함
- 지정 MFC의 전품목 재고 확보 결과가 확인됨
- 필요한 예약 슬롯의 점유 결과가 확인됨
- Payment/PG의 승인 사실과 주문·금액·통화가 일치함
- 센터 제한, 리콜, 품질 보류 등 주문을 막는 조건이 없음

**실행 규칙**

일부 단계가 성공했다는 이유만으로 주문 전체를 확정하지 않는다. 자원 확보 일부 성공 후 나머지 실패 시 결제 진입을 차단하고 성공분 해제를 확인한다. 승인 성공 후 OMS 주문 저장 또는 이행 연결이 실패하면 원주문 복구나 승인된 원거래 취소 보상을 대사한다.

**결과**

주문 확정, 확정 대기, 결제 확인 중, 보상 대기, 확정 거절 또는 수동 조사 필요 상태를 분리한다. 주문 확정은 현장 피킹·포장·라이더 인계가 완료되었다는 의미가 아니다.

#### A.1.5 주문 상태·생명주기 관리 모듈

**책임과 목적**

주문 전체 상태와 주문상품, 이행 단위, 배송 단위, 클레임의 상태를 연결하고 허용된 전이만 적용한다.

**관리 단위**

- 주문 전체: 접수, 자원 확보, 결제 확인, 확정, 준비, 부분 이행, 배송, 완료 등
- 주문상품: 원수량, 이행 수량, 미이행 수량, 취소 수량, 클레임 대상 수량
- 이행 단위: 현장 요청, 수락·거절, 준비, 결품, 포장, 인계
- 배송 단위: 계획, 배차, 실제 인수, 배송 중, 전달, 실패 또는 회수
- 클레임: 신청, 심사, 승인·거절, 회수, 검수, 교환·재배송, 환불, 종결

**상태 전이 규칙**

주문 전체 상태만으로 각 주문상품이나 배송 단위의 실제 결과를 추정하지 않는다. 예를 들어 일부 배송이 완료되어도 다른 배송의 미이행 의무가 남아 있으면 주문 전체 완료로 처리하지 않는다. 고객 취소 신청, 취소 승인, 현장 중지, 실제 인계 중단, PG 취소 성공은 서로 다른 상태다.

**종결 조건**

완료·취소·클레임 종결 전에 남은 실물, 금액, 회수, 검수, 환불, 고객 안내 의무를 확인한다. 교환 승인 건은 재배송 의무도 확인한다. 인계 후 반품은 과거 인계 사실을 삭제하지 않고 별도 회수·검수·환불 기록으로 연결한다.

#### A.1.6 결제 협업·PG 거래 대사 모듈

**책임과 목적**

Payment/PG가 소유하는 실제 거래 사실을 확인하고 OMS의 주문·청구·환불 의무와 대조한다. OMS는 결제 승인·취소를 요청하고 결과를 추적하지만, 실제 거래가 성공했는지는 PG 결과로 확정한다.

**관리 데이터**

- 원주문 ID, 결제 시도 ID, PG 거래 ID 및 원거래 참조
- 요청 금액, 승인 금액, 통화, 거래 상태
- 전체 취소·정책상 허용된 부분 취소·환불 요청 ID 및 멱등성 키
- 취소 요청 금액, 성공 취소 누계, 진행 중 취소 금액, 남은 취소 가능액
- PG 조회 결과, 응답 코드, 미결 사유, 후속 조회·보상 이력

**처리 규칙**

결제창 복귀나 Commerce의 성공 표시만으로 승인을 확정하지 않는다. 타임아웃·응답 유실은 실패가 아니라 결과 불명이다. 결과 불명에서는 원거래를 조회하고 신규 승인이나 중복 결제를 만들지 않는다. 승인액·통화·주문 참조가 일치하지 않으면 확정과 출고를 차단한다.

**취소·환불 처리**

OMS는 원주문 스냅샷을 기준으로 환불 의도와 금액을 산정한다. PG에 전체 취소 또는 현장 결품 시 고객 사전 선택에 따른 정책상 허용된 부분 취소를 요청하고, 성공·실패·결과 불명을 구분한다. 성공한 취소와 진행 중 취소를 함께 고려해 중복 환불을 방지한다. OMS의 환불 의도 등록만으로 고객 환불 완료를 표시하지 않는다.

#### A.1.7 재고 확보·예약·해제 협업 모듈

**책임과 목적**

지정 MFC의 재고를 주문에 확보할 수 있는지 확인하고, 예약·해제·만료·결과 불명·현장 인계 결과를 주문과 연결한다. 재고 원장과 실물 수량은 OMS가 직접 수정하지 않으며, 기존 본문의 소유권 기준에 따라 WMS의 재고 예약·해제 및 물리 수량 결과를 확인한다.

**입력·검증**

- 주문 ID, 주문상품 ID, 지정 MFC, SKU, 수량
- LOT 및 기한 조건, 품질·판매 적격 상태
- 정상 재고, 유효 예약, 안전재고, 보류 수량
- 예약 요청 ID, 예약 ID, 유효시간, 해제 수량·사유

**처리 규칙**

현물 조회만으로 예약 성공을 선언하지 않는다. 전품목 예약이 확인되어야 결제 진입이 가능하다. 다품목 중 일부만 예약되면 나머지 품목 확보를 완료하거나 성공분 예약을 해제해야 하며, 부분 예약 상태에서 결제를 시작하지 않는다. 예약 결과 불명은 원예약 조회로 해소하기 전 중복 예약이나 재판매를 허용하지 않는다.

**현장 사실과의 연결**

피킹 시작 또는 피킹 완료만으로 현물을 차감하지 않는다. 실제 포장 인계 등 승인된 현장 사건과 재고 소유 시스템의 반영 결과를 연결한다. 재고 예약의 요청·확정·해제와 현장 작업의 수락·수행·인계는 별개 결과다.

#### A.1.8 이행 계획·배송 분할 모듈

**책임과 목적**

주문상품을 현장 이행 단위와 배송 단위에 연결하여, 주문의 수량·약속·완료 여부를 추적한다.

**처리 범위**

- 주문상품별 이행 수량과 지정 MFC 연결
- 이행 ID 및 배송 ID 연결
- 배송 방식, 예약 시간, 약속된 이행 조건 보존
- 10kg 초과 주문의 분할배송 단위 생성
- 각 배송 단위의 계획·실제 수행 결과와 주문상품 수량 연결
- 실패·미이행분에 대한 배송 재계획·회수 및 후속 의무 연결

**규칙**

고객 주문과 결제는 하나로 유지하고, 분할배송은 별도의 배송 단위로 추적한다. 분할배송을 이유로 주문이나 PG 결제를 복제하지 않는다. 각 배송 단위의 실제 전달 증빙이 확인된 수량만 완료 집계에 반영한다. 분할배송으로 배달팁을 추가 청구하지 않는 기존 정책을 유지한다.

#### A.1.9 현장 준비·품절·품질 예외 조정 모듈

**책임과 목적**

MFC에서 수행하는 주문 작업을 OMS의 주문상품 및 이행 단위와 연결하고, 수락·거절·피킹·검품·패킹·결품·파손·판매 제한·인계 결과에 따라 주문의 후속 처리를 판단한다.

**연계 데이터**

- 주문 ID, 주문상품 ID, 이행 ID, 지정 MFC
- 작업 요청 ID, 작업 수락·거절 결과
- SKU, 수량, LOT, 피킹·검품·패킹 결과
- 결품·파손·품질 보류·판매 제한 사유
- 작업 중지 요청 및 실제 중지 결과
- 실제 포장 인계 수량·시각·증빙 참조

**처리 규칙**

작업 요청을 전송한 것과 현장이 요청을 수락한 것은 구분한다. 작업 중지 요청도 실제 작업 중지 완료와 다르다. 결품이 발생하면 주문 당시 품절 처리 선택, 고객 동의 조건, 이미 포장·인계된 수량, 취소 가능 수량, 환불 의무를 확인한다. 고객 동의 없이 다른 상품이나 다른 LOT로 자동 대체하지 않는다.

**후속 처리**

미인계 수량은 작업 중지·예약 조정·부분 취소·환불 절차를 판단한다. 이미 인계된 수량은 출고 전 취소로 되돌리지 않고 배송 중 회수 등 별도 의무를 판단한다. 재고·PG 결과는 각 소유 시스템의 확정 결과를 확인한다.

#### A.1.10 배송·회수 협업 모듈

**책임과 목적**

Delivery의 실제 픽업·인수·전달·실패·회수 사실을 주문에 연결한다. 재배송 수행 사실은 교환 승인 건에 한해 교환 클레임과 연결한다.

**Delivery와 연결할 정보**

- 실제 픽업·인수·전달·실패·회수 상태(재배송은 교환 승인 건에 한함)
- 실제 수행 시각, 수량, 사유, 증빙 참조
- 라이더 또는 수행 건의 식별자

**처리 규칙**

라이더 배정, 실제 인수, 고객 전달은 각각 다른 사실이다. GPS 도착·시간 경과만으로 실제 전달을 확정하지 않는다. 배송 실패는 자동으로 주문 전체 취소를 의미하지 않으며 주문상품별 실제 인계 수량과 남은 의무를 기준으로 후속 조치를 판단한다.

#### A.1.11 전체·부분 취소 조정 모듈

**책임과 목적**

고객의 취소 의도를 접수하고, 취소 대상 수량이 실제로 출고 전 취소 가능한지 확인한 뒤 현장 중지, 재고 예약 해제, 배송 취소·회수, 쿠폰·행사 권리, PG 취소, 고객 안내를 조정한다.

**검증 항목**

- 주문·주문상품·취소 대상 수량 및 취소 사유
- 원수량, 기존 취소 수량, 인계 수량, 진행 중 클레임 수량
- MFC 작업 중지 결과 및 실제 인계 상태
- Delivery 고객 배송의 실제 인수·수행 상태
- Delivery의 실제 인수·전달 사실
- 원거래 부분·전체 취소 가능 금액과 진행 중 취소 금액

**처리 규칙**

취소 신청이 먼저 들어왔다는 이유만으로 인계가 취소되었다고 간주하지 않는다. 취소 접수와 현장 중지·실제 인계 판정을 분리한다. 실제 인계 전 중지가 확정된 수량은 출고 전 취소 절차로 처리할 수 있지만, 이미 인계된 수량은 회수 등 별도 업무로 연결한다.

**종결 조건**

주문 상태 변경만으로 취소를 종결하지 않는다. 대상 수량의 현장 결과, 예약 해제·현물 처리, PG 취소 결과, 쿠폰·행사 처리, 고객 안내를 각각 확인한다.

#### A.1.12 교환·반품·회수 관리 모듈

**책임과 목적**

원주문·주문상품과 연결하여 교환·반품 신청의 자격, 수량, 사유, 증빙, 중복 신청, 회수, 검수, 재배송·대체 이행, 환불을 관리한다.

**신청 검증**

- 주문 ID, 주문상품 ID, 신청 수량 및 사유
- 수령 시각과 신청 기한
- 실제 인계·전달된 수량 및 과거 클레임
- 동일 주문상품의 진행 중 교환·반품·환불 수량
- 고객 동의와 필요한 증빙
- 회수·검수·환불의 기존 진행 상태 및 교환 승인 건의 재배송 상태

**처리 규칙**

회수 지시와 실제 회수, 회수와 검수 합격, 검수 합격과 재판매 가능, 환불 의도와 환불 성공은 각각 분리한다. 반품 접수나 회수 완료만으로 재고를 자동 증가시키지 않는다. 재판매 가능 여부는 기존 기준의 상품 종류·온도대·포장·품질 조건을 적용한다.

**수량 관리**

반품·교환·환불 진행 중인 수량은 신청 가능량에서 제외해 같은 수량이 중복 처리되지 않도록 한다. 재배송은 교환 승인에 따른 후속 이행으로만 허용하며 원주문·교환 클레임에 연결한다. 새로운 고객 구매로 중복 생성하지 않는다.

#### A.1.13 환불 의도·금액 산정 모듈

**책임과 목적**

원주문 당시의 가격과 할인 배분 스냅샷을 사용해 환불 대상과 금액을 산정하고, PG 취소·환불 실행 결과와 주문의 환불 의무를 연결한다.

**금액 산정 및 한도**

- 취소·반품 대상 주문상품과 수량을 확인한다.
- 주문 당시 품목 단가와 할인 배분을 사용한다.
- 성공한 취소 금액과 진행 중 취소 금액을 함께 반영한다.
- 원거래의 취소 가능 잔액을 초과하는 요청을 차단한다.
- 전체 취소와 정책상 허용된 부분 취소의 차이를 적용한다. 부분 취소는 현장 결품 시 고객이 사전에 선택한 경우에 한정한다. 반품에 따른 환불은 별도 클레임으로 처리하며, 고객의 임의 부분 취소는 허용하지 않는다.
- 봉투값·배달팁·쿠폰 복원 등 별도 정책 항목을 각각 판단한다.

**연계 및 복구**

OMS는 환불 의도와 계산 근거를 보존하고 Payment/PG에 원거래 참조·금액·멱등성 키를 전달한다. PG 결과가 불명확하면 원거래를 조회한다. 요청을 보냈다는 사실만으로 환불 완료를 표시하지 않는다. 정책상 허용된 부분 취소가 실패하거나 장기 미결 상태이면 주문·클레임을 종결하지 않고 대사 사건으로 관리한다.

#### A.1.14 고객·운영자 조회·상태 전달 모듈

**책임과 목적**

OMS가 소유하는 주문 상태와 관련 시스템에서 확인된 결제·재고·현장·배송·클레임 결과를 조합해 Commerce에 제공한다.

**고객용 결과**

- 주문·주문상품 상태
- 결제 확인 중·승인 확인·실패·취소/환불 진행 상태
- 상품 준비, 부분 이행, 배송 단위별 진행·완료·실패
- 취소·교환·반품·회수·환불의 접수 및 처리 상태
- 고객이 선택하거나 동의해야 하는 후속 조치

**운영자용 결과**

- 주문·주문상품·이행·배송·클레임의 상세 상태
- 연계 요청·응답·결과 불명·재시도·보상 내역
- 재고·PG·현장·배송 간 대사 불일치
- 담당자 조치가 필요한 장기 미완료 사건

**표시 규칙**

확정되지 않은 결과를 성공으로 표시하지 않는다. OMS가 조합한 업무 상태와 소유 시스템이 확정한 실제 사실을 구분한다. 통지 실패는 주문 원장 반영 실패와 분리해 재전송할 수 있도록 한다.

#### A.1.15 분산 작업·복구·감사 모듈

**책임과 목적**

주문 처리에 참여하는 여러 시스템의 단계별 결과를 추적하고, 타임아웃·응답 유실·중복 수신·부분 성공·순서 역전·대사 불일치를 복구한다.

**필수 추적 항목**

- 원주문, 주문상품, 요청, 결제 시도, 예약, 슬롯, 이행, 배송, 클레임 식별자
- 각 단계의 요청 시각·응답 시각·상태·오류 코드
- 재시도 횟수와 다음 확인 단계
- 보상 실행 여부와 실제 결과
- 운영자 상신·승인·조치 사유
- 주문 원장과 PG·재고·현장·배송 결과 간 대사 상태

**복구 규칙**

같은 요청·사건을 다시 수신하면 원결과를 확인하고 중복 반영하지 않는다. 결과 불명 상태에서 새 주문·새 결제·새 예약을 생성하지 않는다. 원장 반영은 성공했지만 통지·조회 갱신만 실패했다면 원장 반영을 반복하지 않고 실패한 후속 단계만 재처리한다. 시간 경과만으로 불명 거래나 예약을 강제로 실패 처리하거나 재판매하지 않는다.

**감사·종결**

운영자 명령, 사유, 변경 전후 값, 대상 주문·거래·예약, 실행 결과와 보상 결과를 기록한다. 자동 복구 한도를 넘는 사건은 미결 상태로 유지하고 후속 대사를 수행한다.

### A.2 OMS와 외부 시스템 간 연계 관계

이 절은 상대 시스템 전체의 하위 구성을 설계하는 것이 아니라, OMS가 업무를 완료하기 위해 주고받아야 하는 연계 계약을 정의한다. 연계 방향은 논리적 책임 기준이며, 모든 항목을 반드시 동기 API로 구현해야 한다는 뜻은 아니다. 요청·응답, 확정 사건, 상태 조회, 비동기 이벤트 중 어떤 방식을 사용할지는 별도 인터페이스 계약에서 정한다.

#### A.2.1 Commerce ↔ OMS: 주문 의도와 고객 주문 결과

**관계의 핵심**

Commerce는 고객의 상품 탐색·장바구니·체크아웃·주문서·고객 화면을 담당한다. Commerce가 주문 의도를 OMS에 전달하면 OMS는 주문 검증, 원장 생성, 자원 확보, 결제 결과 확인, 주문 상태·클레임 처리를 조정한다. Commerce 화면의 주문 제출 성공은 주문 확정이나 결제 승인을 의미하지 않는다.

| 연계 업무 | 방향 | 요청·전달 데이터 | OMS 처리 | 응답·후속 결과 |
|---|---|---|---|---|
| 주문 초안 생성 | Commerce → OMS | 고객 참조, 요청 키, SKU·수량·오퍼, 지정 MFC, 배송지·방식·예약 시간, 쿠폰·품절 선택 | 중복 주문 의도, 판매 상태, 수량 상한, 가격·배송 조건 검증 및 스냅샷 생성 | 초안 ID, 주문 버전, 계산 금액, 검증 결과, 유효시간 |
| 초안·주문 상태 조회 | Commerce → OMS | 주문/초안 ID, 고객 권한, 조회 범위 | 접근 권한 확인 및 OMS 원장 조회 | 주문·주문상품·이행·배송·클레임 상태 |
| 결제 진입 가능 확인 | Commerce ↔ OMS | 초안 참조, 결제 진입 의도 | 가격·쿠폰·행사 권리·재고 예약·필요 슬롯 유효성 확인 | 결제 진입 가능, 보류 또는 거절 사유 |
| 결제 결과 연결 | Payment 결과 및 Commerce 참조 → OMS | 결제 시도·PG 거래 참조, 주문 참조 | PG 원거래·주문·금액·통화 대사 | 승인 확인, 실패 확정, 확인 중, 불일치, 보상 대기 |
| 예약 시간 변경 | Commerce → OMS | 주문 ID, 현재 버전, 새 시간대 | 상품준비 진입·준비 시작 경합, 새 슬롯·재고·LOT 기한·현장 여력 검증 | 새 버전·변경 결과 또는 기존 약속 유지 |
| 전체 취소 및 정책상 허용된 부분 취소 | Commerce → OMS | 주문 ID, 주문상품 ID, 대상 수량, 사유·고객 의도 | 전체 취소 가능 수량과 현장 경합을 판정. 부분 취소는 현장 결품 시 고객의 사전 선택이 있는 경우에만 허용 | 접수·보류·승인·거절 및 처리 단계 |
| 교환·반품 신청 | Commerce → OMS | 주문상품, 수량, 사유, 수령 시각, 증빙, 고객 동의 | 신청 기한·자격·중복·진행 수량·실제 인계 검증 | 신청·심사·회수·검수·환불 상태 및 교환 승인 건의 재배송 상태 |
| 상태·결과 통지 | OMS → Commerce | 주문 상태 변경, 주문상품별 결과, 고객 안내 사유 | 사건 순서·중복·표시 권한 검증 | 고객 화면·주문 이력 갱신 |

**연계 오류 처리**

Commerce의 요청 응답이 유실되면 동일 요청 키로 재조회한다. OMS가 접수했으나 후속 단계가 진행 중인 경우 진행 상태를 반환한다. OMS 원장에는 반영되었으나 Commerce 통지만 실패한 경우 주문 생성이나 상태 전이를 반복하지 않고 통지만 복구한다.

#### A.2.2 Payment / 토스페이먼츠 PG ↔ OMS: 승인·취소·환불 거래 사실

**관계의 핵심**

결제 흐름은 Commerce에서 시작하지만, OMS가 주문 조건과 자원 확보를 검증한 뒤 Payment/PG의 실제 거래 절차로 연결한다. Payment/PG는 승인·실패·거래 조회·원거래 취소 및 환불 결과의 정본이다. Payment/PG는 프로젝트의 8개 분류에 추가되는 외부 연계 참여자이며, OMS 업무상 반드시 구분해 기술한다.

| 연계 업무 | 방향 | 요청·전달 데이터 | OMS 검증·처리 | 결과 |
|---|---|---|---|---|
| 결제 준비 | OMS → Commerce/Payment 흐름 | 주문·초안 참조, 확정 청구액, 결제 시도 참조 | 전품목 재고·필요 슬롯·가격·쿠폰·행사 권리 확인 | 결제 진입 가능 또는 보류 |
| 승인 결과 확인 | Payment/PG → OMS 또는 OMS의 거래 조회 | 주문 참조, 결제 시도 ID, PG 거래 ID, 금액·통화·상태 | 원주문·금액·통화·거래 상태 대사 | 승인 확인·실패 확정·결과 불명·불일치 |
| 결과 불명 조회 | OMS → Payment/PG | 원거래·원요청 식별자 | 신규 승인 없이 원거래 결과 재확인 | 실제 승인·실패 결과 또는 미결 상태 |
| 전체 취소 | OMS → Payment/PG | 원거래 참조, 취소 금액, 사유, 멱등성 키 | 취소 적격성·남은 금액·중복 요청 확인 | 취소 성공·실패·결과 불명 |
| 부분 취소 | OMS → Payment/PG | 원거래 참조, 대상 주문상품·금액, 계산 근거, 멱등성 키 | 원가격·할인 배분·성공/진행 취소 한도 검증 | 부분 취소 결과 및 거래 참조 |
| 환불 대사 | Payment/PG → OMS 조회/결과 | 실제 취소 금액·상태·거래 참조 | OMS 환불 의무와 실제 거래 결과 대조 | 환불 완료·미결·불일치 |
| 보상 취소 | OMS → Payment/PG | 주문 확정 실패 등 승인된 보상 사유, 원거래 참조 | 보상 가능성·중복 요청·원거래 상태 확인 | 원거래 취소 결과 및 주문 후속 처리 |

**정상 결제 흐름**

1. Commerce가 주문서와 결제 의도를 제출한다.
2. OMS가 주문 초안, 가격, 쿠폰·행사 권리, 지정 MFC 재고 확보, 필요한 슬롯을 검증한다.
3. 필요한 자원이 모두 확보된 경우에만 결제 절차로 진입한다.
4. Payment/PG가 실제 승인·실패 결과를 생성한다.
5. OMS가 원주문·승인 금액·통화·거래 상태를 대사한다.
6. 적격한 승인 결과가 확인되면 OMS가 주문을 확정하고 동일 이행 건을 현장에 전달한다.
7. 승인 실패가 확정되면 주문을 미확정으로 유지하고 관련 자원 해제 결과를 확인한다.

**결과 불명·지연 승인 처리**

- 타임아웃을 결제 실패로 단정하지 않는다.
- 원거래 조회가 끝나기 전에 새 승인이나 중복 결제를 만들지 않는다.
- 불명 상태에서는 재고·슬롯·쿠폰·행사 점유를 임의로 해제하지 않는다.
- 승인 성공이 늦게 확인되면 주문을 적격하게 복구할 수 있는지 확인한다. 복구할 수 없으면 승인된 원거래 취소 보상과 실제 결과를 대사한다.
- 승인액·통화·주문 참조가 일치하지 않으면 주문 확정과 출고를 차단한다.

#### A.2.3 WMS ↔ OMS: 재고 확보·해제와 실제 수량 결과

**관계의 핵심**

OMS는 주문별로 재고 확보가 필요한지 판단하고, 지정 MFC의 재고 예약·해제 및 물리 수량 결과를 WMS와 연계한다. 기존 OMS 기준 본문에 따라 재고 원장과 물류 수량 변경은 WMS가 소유한다. OMS는 재고를 직접 차감하거나 예약 성공을 임의 선언하지 않는다. MFC의 현장 작업 결과는 별도로 받아 주문 상태와 연결한다.

| 연계 업무 | 방향 | 요청·전달 데이터 | OMS 처리 | 결과·경계 |
|---|---|---|---|---|
| 판매 가능성·재고 확인 | OMS ↔ WMS | 지정 MFC, SKU, 수량, LOT·기한 조건, 센터 제한 참조 | 정상·예약·안전재고·보류 상태 검증 | 참고 가능한 재고 상태; 조회만으로 예약 성공 처리 금지 |
| 주문 재고 예약 | OMS → WMS | 주문·주문상품 ID, MFC, SKU·수량, LOT 조건, 요청 키 | 전품목 예약 결과 집계 | 예약 ID·수량·유효시간·거절 사유 |
| 예약 해제 | OMS → WMS | 원예약 ID, 해제 수량·사유, 요청 키 | 해제 결과와 주문 미이행 수량 대사 | 해제 성공 확인 후 재사용 가능 상태 반영 |
| 예약 결과 불명 조회 | OMS ↔ WMS | 원요청·예약 ID | 기존 예약의 실제 상태 조회 | 조회 전 중복 예약·재판매 금지 |
| 현장 중지·출고 영향 | OMS → WMS 및 현장 연계 | 주문·이행 참조, 대상 수량, 중지 요청 | 실제 인계·출고 반영 여부 재확인 | 요청 수신과 실제 중지·수량 반영은 별도 |
| 실제 수량 결과 대사 | WMS → OMS 또는 OMS 조회 | SKU·LOT·수량, 센터, 실제 반영 사건·시각 | 예약·현장 인계·원수량 대조 | 불일치는 종결 보류 및 조사 사건 |

**연계 경계**

고객 주문은 지정 MFC의 적격 재고를 대상으로 한다. 센터별 재고와 실제 수량은 해당 재고 원장을 기준으로 확인한다.

#### A.2.4 SCM / Replenishment ↔ OMS: 고객 수요·품절 영향·공급 상태

**관계의 핵심**

SCM은 수요·공급 계획을 담당한다. OMS는 고객 주문 원장과 고객 약속을 소유한다. SCM의 공급 계획 변경만으로 기존 고객 주문을 임의 취소하거나 주문 수량을 변경하지 않는다.

| 연계 업무 | 방향 | 전달 데이터 | OMS의 처리 | 경계 |
|---|---|---|---|---|
| 확정 수요 제공 | OMS → SCM | 확정 주문 수요, SKU, 지정 MFC, 필요한 시점, 주문 참조 또는 집계 참조 | 확정 수요와 미이행 의무를 구분해 제공 | SCM 데이터가 OMS 주문 원장을 대체하지 않음 |
| 취소·품절 수요 변동 | OMS → SCM | 취소 수량, 결품, 미이행 수량 변화, 발생 시각 | 중복 사건 제거 후 수요 변동 반영 | 취소 신청만으로 확정 취소 수요로 처리하지 않음 |
| 공급 상태·지연 수신 | SCM → OMS | SKU·MFC, 수량, 예상 시점, 지연·공급 축소 상태 | 영향받는 주문·재고 적격성·고객 약속 확인 | 예정 공급은 현재 판매 가능한 현물과 다름 |
| 품질 보류·공급 제한 | SCM/WMS 관련 사건 → OMS | SKU·LOT·센터, 제한 종류·범위, 적용 시각 | 신규 예약·이행 가능성 재검증, 기존 주문 영향 조사 | 제한 사실을 확인하지 않고 기존 주문을 자동 종결하지 않음 |
| 공급·수요 대사 | OMS ↔ SCM | 확정 주문, 예약, 취소 및 재고 반영 수량의 구분된 집계 | 중복 차감·이중 집계 여부 확인 | 예측 수요와 확정 미이행 수요를 중복 계산하지 않음 |

**업무 흐름**

SCM이 공급 지연이나 배분 축소를 전달하면 OMS는 영향받는 SKU·지정 MFC·주문 및 수량을 확인한다. 이미 고객에게 확정한 약속과 실제 확보 상태를 검증한 뒤, 기존 OMS 정책에 따라 보류·품절·취소 등 후속 업무를 판단한다. SCM의 추천이나 승인만으로 고객 주문이 변경되지는 않는다.

#### A.2.5 MFC ↔ OMS: MFC 현장 작업·슬롯·준비·인계 결과

**관계의 핵심**

MFC는 MFC 현장 작업, 피킹·검품·패킹·포장 인계, 슬롯·작업 여력, 현장 제한과 실제 작업 결과를 제공한다. OMS는 주문의 사업 판단과 생명주기를 소유하며 MFC의 실제 결과를 주문상품·이행 단위에 연결한다. 재고 원장·예약의 소유권은 기존 OMS 기준 본문의 WMS 경계를 유지하고, 현장 실행 사실과 재고 원장 반영 결과를 혼동하지 않는다.

| 연계 업무 | 방향 | 요청·전달 데이터 | OMS의 처리 | 결과·경계 |
|---|---|---|---|---|
| 슬롯 확보·변경·해제 | OMS ↔ MFC | MFC, 주문 참조, 슬롯, 예약 ID, 버전, 요청 키 | 시간대·준비 시작 경합 및 약속 시간 검증 | 슬롯 점유 성공·실패·불명·해제 결과 |
| 작업 요청 | OMS → MFC | 확정 주문, 주문상품·이행 ID, 약속 시간, 품절 선택, 작업 제약 | 작업 수락·거절에 따른 주문 후속 판단 | 요청 전송과 작업 수락은 별도 |
| 피킹·검품·패킹 결과 | MFC → OMS | SKU·수량·LOT, 실제 작업 결과, 부족·파손·품질 사유 | 주문상품별 이행 수량·품절 정책 판단 | 피킹 완료가 인계 완료 또는 재고 차감 완료를 의미하지 않음 |
| 작업 중지·취소 | OMS → MFC | 작업 참조, 대상 주문상품·수량, 사유·요청 키 | 중지 요청과 실제 중지 결과를 구분 | 인계 경합 여부에 따라 취소 가능 수량 재판정 |
| 실제 포장 인계 | MFC → OMS | 포장/이행 ID, SKU·수량·LOT, 시각, 증빙 참조 | 주문상품 수량·배송 단위·취소 가능 수량 갱신 | 실제 인계 사실과 WMS 재고 반영 결과를 각각 대사 |
| 현장 제한·품질 사건 | MFC → OMS | MFC, 제한 종류, SKU·LOT 범위, 영향 주문, 적용·해제 결과 | 신규 업무 제한 및 기존 주문 영향 평가 | 제한이 기존 환불·회수·안전 의무를 삭제하지 않음 |
| 예약·현장 결과 조회 | OMS ↔ MFC | 주문·작업·슬롯 참조 | 원결과 조회 및 중복 요청 방지 | 조회 실패 시 성공·실패를 추정하지 않고 해당 업무 보류 |

**시간 변경의 경합 처리**

예약배달 시간 변경은 기존 본문에 정한 허용 구간에서만 처리한다. OMS는 새 슬롯과 관련 조건을 확인하고, 실제 상품 준비 시작과 시간 변경 중 어느 결과가 먼저 확정되었는지 판정한다. 준비 시작이 먼저 확정되었으면 변경을 거절하고, 변경 성공 시 새 버전·기존 슬롯 해제 결과를 연결한다. 실패하면 기존 약속을 유지한다.

#### A.2.6 Delivery ↔ OMS: 배송·회수 수행 증빙

**관계의 핵심**

Delivery는 고객 배송에서 라이더의 실제 픽업·인수·고객 전달·실패·회수 수행 사실과 증빙을 관리한다. 재배송 수행은 교환 승인 건에 한해 기록한다. OMS는 해당 결과를 주문상품·이행·배송·클레임 수량과 연결한다.

| 연계 업무 | 방향 | 전달 데이터 | OMS의 처리 | 경계 |
|---|---|---|---|---|
| 실제 인수 결과 | Delivery → OMS | 주문·이행·배송 ID, 인수 수량·시각, 증빙 참조 | 출고 전 취소 가능성 및 배송 상태 갱신 | GPS 도착이나 배차 수락만으로 인수 완료 처리 금지 |
| 고객 전달 결과 | Delivery → OMS | 배송 ID, 실제 전달 상태·수량·시각, 증빙 | 배송 단위 및 주문상품 완료 수량 갱신 | 시간 경과만으로 전달 완료 처리 금지 |
| 배송 실패·사고 | Delivery → OMS | 배송 ID, 실패/사고 코드, 사유, 수량, 증빙 | 배송 재계획·회수·부분 완료·고객 안내 판단. 재배송은 교환 승인 건에 한함 | 실패가 자동으로 주문 전체 취소를 뜻하지 않음 |
| 회수 수행 | OMS 요청 ↔ Delivery 결과 | claim ID, 주문·주문상품·수량, 회수 사유·위치 | 회수 의무와 실제 회수 사실 연결 | 회수 지시와 회수 완료, 회수 완료와 검수 합격은 별도 |
| 교환 승인에 따른 재배송 | OMS → Delivery | 원주문·주문상품·교환 클레임·교환품 수량, 새 배송 참조 | 교환 승인 건의 후속 이행으로 연결 | 교환 외 사유의 재배송 금지; 새 고객 주문·새 결제로 중복 생성하지 않음 |
| 수행 증빙 정정·사고 조사 | Delivery → OMS | 증빙 참조, 변경 사유, 변경 이력 | 기존 결과와 정정 이력을 대사 | 증빙 없이 완료 상태를 강제 확정하지 않음 |

**취소 경합 처리**

고객 취소가 접수되면 OMS는 MFC의 작업 중지 결과와 Delivery의 실제 인수 사실을 확인한다. 실제 인계가 먼저 확정된 경우 출고 전 취소로 처리하지 않으며, 회수·배송 중 취소 등 별도 의무를 판단한다.

### A.4 공통 연계 오류·재시도·대사 규칙

#### A.4.1 오류 유형별 처리

- **명시적 업무 거절:** 판매 중지, 자원 부족, 센터 제한, 권한 부족 등 처리 거절이 확정된 상태다. 거절 사유를 보존하고 조건이 바뀌지 않은 채 무한 재시도하지 않는다.
- **명시적 기술 실패:** 요청이 처리되지 않았음이 확인된 실패다. 해당 업무의 재시도 정책과 요청 멱등성 조건에 따라 재시도한다.
- **결과 불명:** 타임아웃·응답 유실 등으로 실제 반영 여부를 알 수 없는 상태다. 실패로 단정하거나 새 요청을 만들지 않고 원요청·원거래·원예약을 조회한다.
- **중복 수신:** 동일 요청 또는 이벤트가 다시 전달된 상태다. 멱등성 키와 사건 ID를 기준으로 중복 반영을 막고 원결과를 반환한다.
- **순서 역전:** 오래된 상태가 최신 상태 뒤에 도착한 경우다. 버전과 소유 시스템의 최신 상태를 확인하고 과거 사건으로 원장을 덮어쓰지 않는다.
- **부분 성공:** 여러 자원 확보 단계 중 일부만 성공한 상태다. 결제·후속 이행을 차단하고 성공분의 보상 해제 결과를 확인한다.
- **대사 불일치:** 주문 금액과 승인액, 예약 수량과 실제 수량, 계획과 실제 수행 등이 일치하지 않는 상태다. 업무 종결을 보류하고 조사·보상·수동 개입을 기록한다.

#### A.4.2 재시도 원칙

1. 같은 업무 의도를 재시도할 때는 동일한 요청 식별자와 멱등성 키를 사용한다.
2. 결과 불명 상태에서는 새 주문·새 결제·새 예약을 만들지 않는다.
3. 원요청 조회 결과가 확정되기 전에는 자원을 재판매 가능한 상태로 풀지 않는다.
4. 재시도는 상대 시스템의 부하, 중복 실행 영향, 업무 기한을 고려해 제한한다.
5. 원장 반영은 성공했지만 통지 또는 조회 갱신만 실패한 경우, 원장 반영을 반복하지 않고 실패한 후속 단계만 복구한다.
6. 실제 재고·거래·인계 증빙이 확인되지 않은 상태에서 시간 경과만으로 성공이나 실패를 확정하지 않는다.

#### A.4.3 OMS 업무 종결 전 확인 항목

주문·취소·클레임을 종결하기 전에 다음 항목을 각각 확인한다.

- 주문상품별 원수량이 미이행 수량, 유효 인계 누계, 출고 전 취소 누계와 정합적인가?
- 인계 이후 반품·회수는 과거 인계 기록을 삭제하지 않고 별도 수량으로 연결했는가?
- 성공한 환불과 진행 중 환불을 함께 차감해 중복 환불을 방지했는가?
- 재고 예약 해제 또는 실제 인계·수량 반영 결과가 소유 시스템에서 확인되었는가?
- 배송별 실제 전달·실패·회수 결과가 증빙과 함께 확인되었는가?
- 쿠폰·행사·배송 슬롯 등 점유·사용 권리의 확정 또는 해제 결과가 확인되었는가?
- 고객 안내 실패가 원장 상태와 분리되어 관리되는가?
- 남아 있는 고객 약속·회수·검수·환불 의무가 없는가? 교환 승인 건의 재배송 의무도 확인한다.

### A.5 대표 연계 시나리오

#### A.5.1 정상 주문·결제·현장 이행·배송

1. 고객이 Commerce에서 상품·수량·배송지·배송 방식을 선택한다.
2. Commerce가 OMS에 주문 초안 생성을 요청한다.
3. OMS가 고객·상품·가격·구매 제한·지정 MFC·배송 조건을 검증하고 주문 스냅샷을 생성한다.
4. OMS가 WMS와 연계해 지정 MFC 재고 예약 결과를 확인하고, MFC와 필요한 시간대 슬롯을 확보한다. 쿠폰·행사 권리는 해당 소유 영역과 연계해 점유한다.
5. 전품목 자원과 필요한 슬롯이 유효한 경우에만 결제 절차로 진입한다.
6. Payment/PG가 실제 승인·실패 결과를 생성한다.
7. OMS가 원주문·승인액·통화·거래 상태를 대사하고 적격한 경우 주문을 확정한다.
8. OMS가 MFC에 주문 이행 작업을 요청한다.
9. MFC가 피킹·검품·패킹을 수행하고 결품·파손·품질 이상·실제 인계 결과를 전달한다.
10. OMS가 WMS 재고 결과와 현장 인계 결과를 대사하고 주문상품·이행 수량을 갱신한다.
11. Delivery가 실제 픽업·전달 결과와 증빙을 기록한다.
12. OMS가 배송별 사실을 주문상품 수량과 연결해 완료 조건을 판단한다.
13. OMS가 확정된 고객용 상태를 Commerce에 제공한다.

#### A.5.2 결제 승인 결과 불명

1. Commerce 또는 결제창이 결과를 전달하지 못해도 OMS는 결제 실패로 단정하지 않는다.
2. OMS는 Payment/PG에 원거래 조회를 요청하고 원주문·금액·통화를 대사한다.
3. 조회 결과가 불명확한 동안 재고·슬롯·쿠폰·행사 점유를 성급하게 해제하거나 새 결제를 허용하지 않는다.
4. 승인 성공이 확인되면 주문 확정 복구를 수행한다.
5. 주문 확정이 불가능하면 승인된 원거래 취소 보상과 실제 PG 결과를 대사한다.
6. 승인 실패가 확인된 경우에만 관련 자원 해제 결과를 확인한다.

#### A.5.3 현장 결품·부분 취소

1. MFC가 주문상품의 실제 결품·파손·판매 제한 결과를 OMS에 전달한다.
2. OMS는 주문 당시 품절 선택, 고객 동의 필요 여부, 이미 포장·인계된 수량, 취소 가능한 수량을 확인한다.
3. OMS는 미인계 수량의 작업 중지 요청, WMS 예약 조정, 고객 안내를 조율한다.
4. 현장 결품으로 고객 사전 선택에 따른 부분 취소가 적격하면 원주문 스냅샷의 가격·할인 배분을 기준으로 환불 가능 금액을 계산한다.
5. OMS가 Payment/PG에 원거래 부분 취소를 요청하고 실제 결과를 조회한다.
6. WMS의 재고·예약 결과와 Payment/PG의 실제 취소 결과가 각각 확인되어야 관련 의무를 종결한다.
7. Commerce에는 부분 유지·취소·환불 진행 결과를 주문상품 단위로 제공한다.

#### A.5.4 고객 취소와 라이더 인계 경합

1. Commerce에서 취소 요청이 접수되면 OMS는 취소 의도를 기록한다.
2. OMS는 MFC에 현장 작업 중지를 요청하고 Delivery의 실제 수행 상태를 확인한다.
3. OMS는 Delivery의 실제 인수 사실과 WMS의 실제 수량 반영 상태를 조회한다.
4. 실제 인계 전 중지가 확정되면 출고 전 취소 절차를 진행한다.
5. 실제 인계가 먼저 확정되면 출고 전 취소로 처리하지 않고 배송 중 회수 등 후속 의무를 별도 판단한다.
6. 재고 해제·회수·환불·고객 안내는 각 소유 시스템의 결과를 대사한 후 종결한다.

#### A.5.5 반품·회수·환불

1. Commerce가 고객의 반품·교환 신청과 사유·수량·증빙을 OMS에 전달한다.
2. OMS가 신청 기한, 대상 주문상품, 중복 신청, 기존 인계 수량 및 진행 중 클레임을 확인한다.
4. Delivery가 실제 회수 수행 사실을 기록한다.
5. 검수 결과에 따라 지정 업무 영역이 반품품의 품질·재판매 가능 여부를 판정한다.
6. OMS가 교환 승인 건의 재배송 또는 환불 의무를 확정한다.
7. Payment/PG의 실제 환불 결과와 재고 처리 결과를 각각 대사한 뒤 클레임을 종결한다.
