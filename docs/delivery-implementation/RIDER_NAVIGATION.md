# RIDER_NAVIGATION — 라이더 앱 길안내 동작 방식

> 작성일: 2026-11-02 · 관련: `CONTRACTS.md` "라이더 길안내 경로", `DECISIONS.md` §7 (N-01~N-06), `TEST_MATRIX.md`
> 구현: 서버 `delivery-service/.../navigation/RiderNavigationService.java`, 앱 `apps/rider_app/lib/navigation.dart`, `delivery_screen.dart`, `navigation_links.dart`

**요약:** 서버가 카카오 길찾기로 경로를 **가끔 한 번** 받아 오고, 앱이 그 경로 위에서 현재 위치를 **매번 계산**한다. 위치가 바뀔 때마다 카카오를 부르지 않는다.

라이더 앱에는 두 가지 길안내가 있다.

| 방식 | 경로 계산 | 음성 | 차종 | 필요 조건 |
|---|---|---|---|---|
| ① 앱 안 안내 ("앱 안에서 안내") | 서버 → 카카오모빌리티 자동차 길찾기 | 없음 (화면 표시) | 자동차 경로 기준 | 서버 카카오 REST 키 |
| ② 카카오내비 ("카카오내비") | 카카오내비 앱 | 있음 (턴바이턴) | **이륜차** | 휴대폰에 카카오내비 앱 |

기존 카카오맵 링크(자동차 경로, 외부 앱/웹)도 그대로 둔다.

---

## 1. 경로 받기 — 서버 (가끔만)

라이더가 "앱 안에서 안내"를 누르면 앱이 요청한다.

```
GET /api/rider/deliveries/{deliveryId}/navigation?target=MFC|DESTINATION[&lat=..&lng=..]
```

서버(`RiderNavigationService`) 처리 순서:

1. **권한·상태 확인**
   - 현재 배정된 라이더만 요청 가능 (그 외 `403`).
   - 픽업 전(`ASSIGNED`·`ARRIVED_AT_MFC`)에는 목적지 `MFC` 만, 픽업 후(`PICKED_UP`·`IN_TRANSIT`·`ARRIVED_AT_DESTINATION`)에는 `DESTINATION` 만 허용 — 전달지는 픽업 후 공개 원칙 유지.
   - 종료·취소된 배송은 `409 DELIVERY_FINISHED`.
2. **출발점 결정**
   - 실 GPS 배송(`DEVICE_GPS`): 앱이 보낸 휴대폰 좌표, 없으면 서버 최신 위치.
   - SIMULATED 배송: 휴대폰 좌표는 **무시**하고 서버가 받은 시뮬레이터 최신 위치만 사용. 위치가 없으면 `409 NO_CURRENT_LOCATION`.
3. **카카오 호출:** 카카오모빌리티 자동차 길찾기(`/v1/directions`, `summary=false`)를 서버 REST 키로 호출.
4. **응답에서 두 가지를 꺼낸다**
   - `sections[].roads[].vertexes` → 도로를 따라가는 좌표 수백 개 = 경로선 `points`
   - `sections[].guides` → 회전 지점 목록. 예: `{좌표, "우회전", "해운대구청어귀삼거리"}`
5. **유료 API 보호:** 같은 배송·목적지·라이더는 **15초** 안에 다시 요청해도 카카오를 부르지 않고 직전 결과를 `cached:true` 로 돌려준다. 직전 조회가 실패했으면 `429 NAVIGATION_RATE_LIMITED`.
6. **실패 처리:** 카카오 실패 시 `503` + 카카오 오류 코드. **직선 경로로 대체하지 않는다.**

## 2. 진행 계산 — 앱 (위치가 올 때마다)

앱(`navigation.dart`)은 받은 경로선을 들고 있다가, 새 위치가 들어올 때마다 서버 호출 없이 직접 계산한다.

```
경로선:  A ────●──────────── B ───────── 목적지
              ↑ 투영점        ↑ 회전 지점(우회전)
              │
          현재 위치
```

1. **경로상 거리 준비 (경로를 받았을 때 한 번)**
   - 경로선의 각 점이 출발점부터 몇 m 지점인지 누적 거리를 계산해 둔다.
   - 회전 지점들도 경로선에 투영해 "경로 위 몇 m 지점"인지 구해 둔다.
2. **투영 (위치마다)**
   - 현재 위치에서 가장 가까운 경로 구간을 찾아 그 위로 수직으로 내린 점(투영점)을 구한다.
   - 투영점까지의 거리 = **경로 이탈 거리**, 투영점의 경로상 거리 = **지금까지 온 거리**.
   - 수 km 범위라 현재 위치를 원점으로 한 평면 좌표(등장방형 근사)로 계산한다.
3. **표시 문구**
   - 다음 안내: 현재 지점보다 10m 이상 앞에 있는 첫 회전 지점(출발지 안내 제외) → `"(회전 지점 거리 − 현재 거리) 앞 우회전 · 도로명"`
   - 남은 거리: 전체 경로 길이 − 현재 거리
   - 남은 시간: 카카오 예상 소요시간 × (남은 거리 ÷ 전체 거리)
   - 남은 거리 30m 미만: `"목적지 근처입니다"`
   - 거리 표기: 1km 미만은 10m 단위(`290m`), 이상은 0.1km(`1.3km`)

예 (에뮬레이터, 카카오 실경로): `1.4km 앞 신해운대역 기장 방면으로 왼쪽 직진 · 운촌삼거리 / 남은 3.1km · 약 11분` → `580m 앞 해운대구청 방면으로 우회전 · 해운대구청어귀삼거리` → `목적지 근처입니다`

## 3. 경로 이탈과 재탐색

- 경로선에서 **50m** 넘게 떨어지면 이탈로 본다.
- 이탈이 **2회 연속**일 때만 서버에 새 경로를 요청한다 — GPS 가 한 번 튀었다고 유료 호출을 하지 않기 위해서.
- 서버의 15초 제한이 함께 걸려 있어, 계속 벗어나 있어도 카카오 호출은 최대 15초에 한 번.
- 픽업이 끝나 목적지가 MFC → 배송지로 바뀌면 자동으로 새 경로를 받는다.
- 배송이 종료되면 길안내를 끈다.

(15초 · 50m · 2회 연속 · 30m 는 2026-11-02 사용자 확정값. 실기기 주행 후 재검토 가능 — `DECISIONS.md` N-03·N-04)

## 4. 현재 위치는 어디서 오나

- **실 GPS 배송:** 휴대폰 GPS 측정값(`LocationReporter`). 같은 값이 서버로도 전송된다.
- **SIMULATED 배송:** 서버 시뮬레이터가 넣은 위치가 실시간 연결(STOMP `/topic/riders/{riderId}`)로 앱에 내려온다.

길안내는 이 위치를 **읽기만** 하고 배송 상태는 바꾸지 않는다. "목적지 근처"여도 고객 도착·전달 완료는 라이더가 직접 요청해야 한다.

## 5. 카카오내비 버튼

위 계산을 쓰지 않는다. 공식 `kakao_flutter_sdk_navi` 2.1.0 으로 목적지 좌표(WGS84)와 차종 **이륜차**(`VehicleType.twoWheel`)만 카카오내비 앱에 넘기고, 경로 탐색·음성 안내·재탐색은 카카오내비 앱이 휴대폰 GPS 로 처리한다. 카카오내비가 없으면 설치 페이지를 연다.

SIMULATED 배송에서는 카카오내비가 휴대폰 실제 위치 기준이라 시뮬레이션 위치와 맞지 않는다(화면에 안내 문구 표시).

## 6. 한계

- 앱 안 안내는 **음성 없음**, 화면 표시만.
- 카카오 길찾기 API 가 **자동차 경로**라 이륜차 전용·통행 제한 도로 규칙은 반영되지 않는다(화면에 표시).
- 남은 시간은 교통 상황을 다시 반영하지 않는다 — 경로를 다시 받기 전까지 처음 예상 시간을 거리 비율로 나눈 값.
