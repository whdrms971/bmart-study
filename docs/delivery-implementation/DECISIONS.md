## 3. 구현 선택 [설계 제안]

| ID | 선택 | 이유 |
|---|---|---|
| S-01 | 단일 Spring Boot 4.1 서비스 + 책임별 패키지 | 기존 서비스 경계 코드 없음 (CLAUDE.md §3.1) |
| S-02 | H2(PostgreSQL 모드) 로컬·테스트, Flyway 마이그레이션은 PostgreSQL 호환 SQL | Docker 미기동. `postgres` 프로필 제공하나 **[미검증]** |
| S-03 | 상태 전이: 배송 행 비관적 락(SELECT … FOR UPDATE) + `@Version` | 동시 수락·인계/취소 경합 단일 결과 |
| S-04 | Transactional Outbox + 스케줄 relay(HTTP POST) + Mock OMS inbox `(sourceSystem,eventId)` | D-14 |
| S-05 | 인증: HS256 JWT(Spring Resource Server). local-test는 테스트 계정 로그인 엔드포인트 제공 | 기존 Auth 서비스 없음. 운영 IdP 연동 시 교체 |
| S-06 | 실시간: STOMP over WebSocket(`/ws`), CONNECT 시 JWT 검증, SUBSCRIBE 시 주문 소유권 검사 | D-06 |
| S-07 | 위치 모드는 **MFC/테스트 시나리오 설정으로 서버가 배송 생성 시 고정**. 앱이 보내는 source 값은 신뢰하지 않음 | CLAUDE.md §3.2 |
| S-08 | 카카오 지도 Flutter: `kakao_map_sdk` 1.3.1 (verified publisher yhs.kr, BSD-3, Android 네이티브 `com.kakao.vectormap` 래퍼). **서드파티** 패키지임 | pub.dev 확인. 카카오 Maps SDK 자체 약관은 카카오 콘솔 기준 |
| S-09 | 시뮬레이터 시간: 결정적 가상 시계. 시뮬레이션 좌표의 `measuredAt`=가상 시각, 서버 `receivedAt`=실시각 별도 저장 | 배속 시 미래 시각 오판 방지 |
| S-10 | 시뮬레이션 위치도 `LocationIngestService`(실 GPS와 동일)를 통과. 주입은 서버 내부 어댑터만 가능, HTTP로 `source=SIMULATED`를 받는 경로 없음 | CLAUDE.md §A-1② |
| S-11 | FIXTURE 경로는 **직접 작성한 좌표열**(도로 정확성 보장 안 함). 카카오 응답은 저장·재사용하지 않고 메모리에만 보관 | 약관상 캐싱 조건 미확인 |

## 4. 고객 도착 판정 (2026-11-02 사용자 결정 → 구현)

기존 문서 확인: `Delivery-business-logic.md` §5.1 은 `가게 도착 → 픽업 완료 → 고객 도착 → 전달 완료` 순서와 "GPS 위치만으로 픽업·전달 완료 처리 불가"만 정하고 거리 기준은 없음 → 충돌 없음. 고객 도착은 OMS 이벤트 계약(§7)에 없으므로 이벤트 추가·변경 없음.

| ID | 결정 | 구현 |
|---|---|---|
| A-01 | 배송지 좌표 기준 직선거리 **150m 이하**에서만 고객 도착 허용, 초과 거부. 거리는 지표면 최단거리(Haversine) | `ArrivalPolicy` — `Geo.distanceMeters`(R=6,371,008.8m), 0.01m 반올림 후 비교. 초과 `409 ARRIVAL_TOO_FAR` |
| A-02 | 인증된 담당 라이더의 최신 위치만 사용. 측정 후 **30초 이내**, 정확도 **50m 이하**(설정값 분리). 없거나 부정확하면 재측정 요청 | 최신 위치의 `riderId` 가 현재 담당 라이더가 아니면 위치 없음 처리. `delivery.arrival.max-distance-meters / max-location-age-seconds / max-accuracy-meters` (환경변수 `DELIVERY_ARRIVAL_*` 로 조정). 미설정 시 도착 차단. 위반 `422 LOCATION_REMEASURE_REQUIRED` |
| A-03 | 정상 판정 불가 시 예외 요청. 라이더의 임의 해제 금지. 관리자 승인 시 사유·거리·정확도·처리자·시각 기록 | `delivery_arrival_exception`(V2) + `ArrivalExceptionService`. 라이더는 요청만, `/api/admin/**`(ADMIN) 만 승인/반려. 처리 사유 필수. 상태 이력에도 기록 |
| A-04 | 배송 중(IN_TRANSIT)만 도착 처리, 도착과 완료는 별도 상태, 중복 요청 멱등, 서버·앱 양쪽 검증 | 서버: 담당 라이더 → 이미 도착이면 멱등 200 → IN_TRANSIT 아니면 `409 INVALID_DELIVERY_STATUS` → 위치·거리 판정. 앱: 같은 규칙으로 사전 판정해 버튼 비활성·안내 |
| A-05 | 운영 정책과 시뮬레이터 분리, 시뮬레이션도 150m 검증, 테스트 우회는 운영 격리·이력 | **우회 기능을 만들지 않음.** 시뮬레이션 위치도 같은 판정을 통과. 테스트에서 먼 거리 도착이 필요하면 관리자 예외 승인(이력 남음)을 사용 |

### 구현 선택 [설계 제안]

| ID | 선택 | 이유 |
